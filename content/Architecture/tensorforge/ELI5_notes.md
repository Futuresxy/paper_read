# TensorForge: Synthesis-Backed Design Space Exploration of Multi-Precision Tensor Core Microarchitectures 通俗讲解

### 0. 整体创新点通俗解读

可以把 TensorForge 理解为比较不同车间布局的试制平台：乘法器是加工工位，对齐和规格化是加工前后的处理设备，点积长度决定多少件产品共用一套后处理设备。把许多乘积先归约再规格化，往往比给每个乘加都配置后端省资源；但长流水仍要持续拿到原料，不能只看机器的标称产能。

全共享像一套设备切换加工所有产品，设备数量少，却需要复杂切换和控制；FP/INT 分组共享像把不同工艺分成两个车间，保留部分重复设备，换取更简单的通路与较低功耗。LUT-FP4 像为有限的输入组合预先准备结果表。这个类比只能帮助理解共享粒度，不能代替指数处理、定点位宽和舍入的精确数学含义。论文真正提供的是在给定约束和评估流程下比较这些选择的方法，而非无条件适用的唯一最佳 Tensor Core。

### 1. 点积后端摊销与阵列组织

多个乘法可以共用一次“整理和入账”，因此每份结果的后处理成本下降。但批次更大，需要持续供料，也可能减少同时处理不同输出的灵活性。判断是否合算，要同时看后端数量、供数和任务形状。

### 2. 数值可行域与随机舍入

把每一笔小金额立刻四舍五入，可能不断丢掉零头；先合并一批再入账可以保住部分零头。随机舍入让进位机会随零头大小变化，但它不能消除输入量化误差，也不保证每次得到同样的最后一位。

### 3. 全共享与分族共享

所有产品共用一条生产线，机器最少，但切换装置和控制可能复杂。把工艺差异较大的产品分成两条线，可以减少切换开销。哪个更省要看产品组合，不能只数机器，也要看运转时的耗能。

### 4. LUT-FP4与系统供数

输入种类很少时，可以直接查“乘法口诀表”。但查到的结果仍要合并、缩放和累加，供料不足时查得快也没用。论文因此既比较小单元，也把它放进 GPU 看能否持续工作。
