## 1. 摘要

TensorForge 是面向多精度 Tensor Core 的综合驱动设计空间探索框架。它用 Chisel 将乘法器、指数处理、对齐移位、归约树、规格化和累加器参数化，生成可综合 RTL，在精度覆盖、峰值吞吐与目标频率约束下比较不同计算组织和共享方式。论文覆盖 600 多种配置、4500 多次综合，研究 DP 相对乘加树的收益、中间精度与累加精度、全共享与分组共享的边界，以及 LUT-FP4。主要结论是在所测条件下，较大的点积长度能摊薄后端开销；全共享通常最省面积，但 FP/INT 分组共享能取得更好的面积—功耗折中。论文还把生成的单元集成到 Ventus，进行系统级评估。需要区分单元综合、存储建模与系统周期评估，不能把这些结果视为流片实测或所有工作负载上的普遍最优。

## 2. 背景知识与核心贡献

多精度支持不仅是给数据类型增加一个解码器。不同浮点格式的指数范围、有效数宽度和归约需求不同，整数又有不同的符号与位宽要求。为每种格式配置专用电路会重复硬件，而全部复用则可能增加选择器、扇出和关键路径压力。另一方面，相同乘法数量可以组织成许多短点积或少量长点积，二者后端数量、数据供应与舍入边界并不相同。因此单看支持格式或峰值 TOPS，无法说明真实成本。

TensorForge 的贡献是把这些选择置于同一生成和综合流程。与主要探索数据流和映射的分析模型不同，它的对象是可综合的算术数据通路和广播式计算阵列。它把精度集合、计算族、阵列组织、点积长度、FP4 实现、共享族、中间精度、累加器精度、舍入与流水放置显式化，再筛选满足目标条件的候选。

阅读时应注意三个边界：生成器覆盖许多配置，不等于一个运行时实例实现所有配置；等峰值吞吐不等于实际工作负载的等吞吐；跨论文工艺归一化只是近似比较。所给 PDF 为匿名稿，不能仅因文件名含 ICCAD 就推断会议录用。

## 3. 核心技术和实现细节

### 0. 技术架构概览

数据流从精度和计算规模约束开始。生成器选取 FP、FP/INT 混合、专用 INT 或 LUT-FP4 包装器，组合乘法、指数、移位、加法树、规格化和累加积木，再实例化为不同内积维度的计算阵列。输入解码后，乘法分支生成有效数乘积，指数分支计算对齐依据；移位器完成对齐并按中间位宽截断，加法树归约多个乘积，后端规格化、舍入并以 FP16/FP32 累加。LUT-FP4 则用输入编码查表产生定点值，再进入局部和全局归约。

共享层面，全共享候选通过模式选择复用算术模块；混合候选分别实例化 FP 与 INT 分支，只在族内共享。流水位置也是配置项，不能把结构差异与不同时序预算混为一谈。RTL 通过 Verilator 验证和综合评估，存储用 CACTI 建模；选定的 8×4×8 Tensor Core 经 operand collector 从寄存器堆取数，集成到 Ventus SM。解读：整个流程是候选生成、约束过滤、成本测量、帕累托筛选及系统验证的闭环，而非一次综合即可代表全部架构。

### 1. 点积后端摊销与阵列组织

DP 单元将 k 对乘积对齐后送入归约树，再进行规格化、舍入和累加。与包含多个浮点后端的乘加树相比，它把后端成本摊到更多乘积上，所以 k 增大时单位运算成本通常下降。论文在相同峰值规模下同时改变 m、n、k，而不是简单给原数组追加乘法器。k=1 对应外积组织，k>1 对应不同长度的内积阵列。

解读：若计算规模固定，增加 PE 内 k 通常意味着减少其他维度的独立单元，但具体组合必须服从阵列定义。后端减少会改变每周期独立结果数、累加状态数量和供数方式；这不是免费提高所有任务吞吐。图 12 中 GEMM 与 attention 的活动率差别说明，单元收益仍需系统利用率支撑。论文给出的边界是所测 FP16/BF16/TF32 及流水时序条件下的综合结果，不能推广成全部数值合同和布局条件下的定理。

### 2. 数值可行域与随机舍入

中间精度控制对齐后、规格化前保留的位数，累加精度控制存储部分和的格式，二者不是同一参数。短点积结果反复写回低精度累加器会产生舍入和 swamping：部分和变大时，新增的小量可能低于可表示步长。增加 k 能减少整条长点积中的舍入次数，但无法自动保证与逐 FMA 或任意商业 GPU 位一致。

随机舍入根据被舍弃部分与随机数决定是否进位，可以减小长期舍入偏差，代价依赖随机数源及控制实现。论文报告面积约增加 0.63%，并以高斯点积和 RTE 任务评估数值可行性。解读：约 20 位的经验阈值取决于误差指标、输入分布和模型，不能替代溢出、次正规数、scale 极值或大数抵消测试。复现时应明确参考运算的输入是否已量化，以及中间截断发生的准确边界。

### 3. 全共享与分族共享

全共享数据通路以格式超集覆盖多种精度，通过模式选择复用乘法器、指数逻辑、规格化和累加模块；专用设计则为各模式保留独立单元。混合策略在 FP 与 INT 两族之间拆分，在各自族内复用。有效数乘法还可以采用宽乘法器打包小操作，或者小乘法器拼接宽操作，两种方式都需要计算交叉项、选择器和路由成本。

18 种策略的综合结果显示，全共享对固定 k 和频率通常面积最小，但全局选择与更宽通路可能增加功耗和关键路径压力；FP/INT 分族方案取得更稳健的帕累托前沿。解读：这反映的是面积与功耗的共同优化，不意味着最小面积点无价值，也不意味着分族永远最好。共享面积节省与共享控制成本应分别量化；同一精度的峰值容量和多模式同时执行能力也应分开陈述。

### 4. LUT-FP4与系统供数

两个四位输入编码只有 256 种组合，因此可用查表生成固定点积项，替代常规有效数乘法、指数计算与对齐的一部分处理。256 是输入编码对数量，不意味着有 256 个互异的数值乘积。图 1(e) 显示小组局部求和、跨组归约、截断、规格化与累加；不能把整条数据通路理解为只查一次表。

论文在所测实现中观察到 LUT-FP4 的面积与功耗收益，尤其是较大 k。所选 Tensor Core 最终经 operand collector 从 Ventus 寄存器堆取数，阵列活动率决定峰值能力能兑现多少。解读：查表的收益依赖综合结果、寄存器、选择网络及 scale 处理位置；FP4 元素查表不等于已经消除 MX/NVFP4 的缩放成本。系统级比较还应保持精度、工作量及访存边界一致，不能把 FP4 Tensor 与 FP32 Vector 的收益只归因于微架构。

## 4. 实验方法与实验结果

## 评估方法

论文采用 TSMC 22 nm、TT 25°C 和 Synopsys Design Compiler X-2025.06，主要目标频率 1.41 GHz，并扫描 1.25、1.30、1.35、1.40、1.41、1.45、1.50 GHz。600 多种配置共进行 4500 多次综合；片上存储通过 CACTI 7 建模。数值实验包括 200 次 4096 维独立高斯向量点积，以 FP64 为参考，以及模拟中间截断的 Qwen3-0.6B / SuperGLUE RTE 评估。没有报告流片后的芯片实测。

| 比较 | 稿件报告的结果 | 应保留的条件 |
| --- | --- | --- |
| DP 与乘加树，典型 FP16、k=16–64 | 面积减少约 47%–55%，功耗减少 25%–36% | 同工艺、综合流程、时序目标、流水深度和峰值计算规模 |
| FP16、k=128 | 面积收益约 57%，功耗节省接近 40% | 不能据此推出任何供数条件下都应选最大 k |
| 中间精度扫描 | 所测格式约 20 位时误差低于 10^-7，RTE 准确率在附近趋于饱和 | 实验性的数值可行性，不等同于位精确复现商业 GPU |
| 随机舍入 | DP 单元面积增加约 0.63% | 需区分随机源实现与实际配置 |
| LUT-FP4 对常规 FP4 | 功耗减少 24.27%–44.91%，面积减少 18.30%–40.15% | 所测数据通路、k 和输出条件 |

共享策略实验比较 18 种方案。全共享通常面积最小，FP/INT 分组共享在所测 k 与频率下有较稳定的面积—功耗前沿。解释用代理模型基于 560 个综合样本，七折交叉验证面积/功耗平均 MAPE 为 3.45%/2.55%，R² 为 0.9930/0.9965；报告的主要结论仍依据综合点，而非只依据代理预测。

对既有工作的比较必须区分原工艺与归一化。相对文献 [9]，原节点比较的 FP8 面积/能效为 2.93×/5.52×，FP4 为 1.49×/3.62×；归一化到 22 nm 后对应为 2.42×/3.60× 和 1.59×/1.84×。摘要另给出保守跨基线汇总：FP8 1.77×/1.49×，FP4 1.35×/3.04×，不能把不同口径合并为同一基线。

Ventus 案例中 Tensor Core 占 SM 面积 27.7%。其 FP4 峰值为 2.89 TFLOPS，面积 0.505 mm²、功耗 0.345 W，对应 5.71 TFLOPS/mm²、8.36 TFLOPS/W。对照向量单元是 FP32，因此约 32× 吞吐差异同时包含精度变化，不能解读成同精度架构收益。系统图显示 GEMM 的周期收益和活动率高于 attention；Tensor 路径 IPC 更低但总周期更少。

局限：中间位宽的任务结果只覆盖给定模型和任务；归一化不是同工艺重实现；综合面积不等同于布局布线或芯片实测面积。表 4 的行标签跨行排版较复杂，建议结合原图审查；本文保留原表数字，不替作者重排或修正。
