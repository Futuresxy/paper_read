## 0. 论文基本信息

**作者 (Authors)**: Hardik Sharma, Jongse Park, Naveen Suda, Liangzhen Lai, Benson Chau, Vikas Chandra, Hadi Esmaeilzadeh

**发表期刊/会议 (Journal/Conference)**: ISCA 2018

**发表年份 (Publication Year)**: 2018

## 1. 摘要

Bit Fusion针对DNN推理中位宽随模型和层变化、硬件却常固定精度的矛盾，提出运行时逻辑融合小乘法器。每个BitBrick处理2位操作数；含16块的融合单元可形成16个二值或三值引擎、4个8位输入×2位权重引擎，或1个8位×8位引擎，并通过时分计算扩展到16位。低精度由此既能释放乘加并行度，也能通过紧凑存储减少数据搬运。

论文将这一机制与二维脉动阵列、按位宽供数的缓冲组织和分块Fusion-ISA结合，覆盖CNN及循环网络。八个模型的45nm综合与周期仿真显示，同面积、同频比较Eyeriss，几何平均加速3.9倍、能耗降低5.1倍；对Stripes为2.6倍与3.9倍。

这些结果来自综合和建模，没有Bit Fusion芯片实测。保持精度的前提来自既有量化模型，部分模型还扩大了通道数；16nm GPU比较另含工艺缩放假设。解读：论文的价值在于建立低位宽计算、存储和编程接口之间的协同关系。

## 2. 背景知识与核心贡献

神经网络推理的大部分工作是乘加，但不同网络、不同层对数值精度的要求并不相同。论文统计，八个模型的乘加占比均超过99%，平均97.3%的乘加可采用不超过4位的配置。若硬件始终使用16位乘法器，低位宽数据虽然能放入其中，释放出的位资源却未必能执行更多独立计算；若硬件固定为二值或三值，又难以容纳需要更高精度的首尾层。因此，问题是如何在保留模型所需精度的同时，把位宽降低转化为实际执行收益。

其数学机会来自乘法的位级成本：两个操作数的位宽分别缩小，部分积数量近似按两者乘积减少，加法成本则主要随位宽线性变化。不过，计算量减少只是条件之一。数据若仍按较宽格式存储和传输，或者每个小计算单元仍配置完整累加器与本地存储，通信和控制开销就可能吞掉收益。

已有位串行方案通过多个周期处理位片，获得精度灵活性，但需要移位、累加和状态保持；部分方案仅支持一侧操作数位宽变化。正文对Stripes究竟哪一侧可变存在表述冲突，应保留这一不确定性。专用二值加速器适用范围较窄，稀疏加速器则利用零值跳过，属于另一种可结合的机会。

Bit Fusion的贡献包括可组合BitBrick、配套脉动阵列与紧凑供数机制，以及将配置成本摊到整层的Fusion-ISA。它使用已有量化网络，并未提出新的量化训练方法。“无精度损失”依赖这些网络及其训练或扩宽条件，论文也没有给出逐模型准确率复核表，不能据此推断任意网络都能直接降到低位宽。

## 3. 核心技术和实现细节

### 0. 技术架构概览

执行从已有量化模型及其分层位宽开始。软件把卷积、全连接或循环层表示为指令块，setup指定输入和权重位宽，同时配置融合方式与供数选择逻辑。块内使用循环、地址生成和计算指令描述数组遍历，配置成本由大量重复操作分摊；本文评估采用层内固定配置。

输入、权重和输出通过显式装载与存储指令在片外内存和片上IBUF、WBUF、OBUF之间交换。输入与权重按所需位宽紧凑存储，缓冲读出一行后先进入寄存器，再由多路选择器分次提供操作数，减少重复访问SRAM数据阵列。每个融合单元只配局部权重缓冲，输入缓冲位于阵列左边界，输出缓冲位于底部。

二维脉动阵列沿行向右共享输入，沿列向下传递部分和。融合单元内部，BitBrick生成2位乘法的部分积，移位加法树按位片权重组合结果，再与流入的部分和相加。16块可在单周期支持最高8位×8位；16位×16位采用四周期时分组合。低位宽模式下多个Fused-PE并行贡献同一个点积，最终输出数并不随引擎数同比增加。

图4中，4N个8位输入与4N×M个2位权重相乘，每个单元组成四个8×2引擎。各行共享输入，各列归约结果，部分和与最终结果保留32位。列底累加器完成汇总，再经激活或池化单元写入OBUF，随后存回片外或与后续兼容层衔接。

循环分块让数据适配片上容量，循环重排改变复用顺序；计算与激活等资源可通过层融合减少中间写回。阵列省去融合单元内独立的输入、输出和部分和缓冲，但仍包含行寄存器及列累加状态。

### 1. 位片乘法分解

组合能力建立在乘法展开式上：把一个长操作数拆成高、低两段，两段之间以2的幂次区分位置；两个操作数相乘就得到四项子乘积，再移位求和。图6的无符号算例为11×6：11=2×4+3，6=1×4+2，因此结果为2×1×16+2×2×4+3×1×4+3×2=66。四项均可由2位乘法器完成，移位量分别为4、2、2、0。

BitBrick通过符号控制，将两个2位输入分别作符号扩展或零扩展，再使用3位有符号乘法器生成6位结果，因此能够处理有符号或无符号位片。解读：将展开式用于补码时，高位片与低位片的符号解释必须正确，不能把每段都按同一种有符号数处理。

当一侧位宽缩小时，需要的交叉项减少。图7把四块资源用于两项4位×2位乘法的求和，得到15×1+10×2=35。对2、4、8位配置，理想情况下单项乘法所需块数为两侧2位片数量的乘积，所以8×8占16块，8×2占4块，2×2占1块。

代价是额外的移位、加法和路由控制。文中支持的常用配置按2的幂组合，不能把标题中的位级灵活性理解成所有整数位宽都具有独立最优实现。二值数据也使用同一BitBrick，最低物理粒度仍为2位；理论并行度还需足够的点积项和供数能力才能兑现。

### 2. 空间融合与时分折中

时分参考设计让每个小乘法器跨周期生成部分积，再经移位和寄存器累加；一个4位×4位乘法需要四周期。虽然乘法器很小，移位器和累加器却要覆盖最高支持位宽。作者指出，支持到16位时，这两部分占据约90%的面积，限制了小乘法器带来的收益。

空间融合把多个BitBrick的部分积在同一周期送入共享移位加法树，末端使用共享累加状态。四块资源可执行一个4×4、两个4×2或四个2×2乘法，改变的是位片组合方式。图10比较含相同数量2位乘法器的局部设计：时分参考与融合单元面积分别为4905和1394μm²，约减少3.5倍；功耗为1712和538，表头单位标为nW，约减少3.2倍。寄存器面积1454降至91μm²，是明显的节省来源。这些属于45nm综合数字，其对象是局部单元。

完整设计进一步采用空间与时间结合。若用64块完全空间实现16位乘法，最低位宽模式的供数接口需扩到128位，增加SRAM组织成本。论文最终每单元保留16块，空间覆盖到8位，16位×16位通过四周期组合完成。

解读：这个选择同时优化小乘法器数量、共享归约电路和存储接口，较高精度承担更多周期。图10支持的是该局部实现的面积与功耗优势；整机性能和每次推理能耗还需结合图13、图18及访存行为判断。

### 3. 紧凑供数与脉动复用

低位宽需要贯通存储与运算。若2位权重仍独占一个宽存储位置，计算单元节省的资源无法同步减少搬运。Bit Fusion按所需位宽保存数据，缓冲读取一行后暂存在寄存器中，由多路选择器分次挑选操作数，减少重复访问SRAM数据阵列。

图4给出具体配置：4N个8位输入乘以4N×M个2位权重，N×M个融合单元各形成四个8×2引擎，共4NM个引擎并行。一次32位输入读取可提供四个输入；一次32位权重读取可容纳16个2位权重，随后按需供给。论文报告，该配置相对宽位权重模式将并行度提高四倍，并将权重缓冲数据阵列访问减少四倍。这里的32位是局部缓冲访问宽度，不能理解为整个阵列只需要32位总流量。

阵列还沿行复用输入、沿列传递部分和，省去每个融合单元内独立的输入和部分结果缓冲。部分和与最终结果采用32位，低位宽主要作用于乘法操作数。相对Eyeriss，局部寄存器文件能耗下降，同时部分访问转移到SRAM；DRAM能耗占比升高也不等于其绝对能耗上升。

解读：计算密度提高后，带宽可能成为新的约束。正文中增宽带宽及扩大批量均对循环网络帮助更大，批量64后收益趋于饱和。批处理通过复用权重提高执行效率，但这些结果不足以说明单个请求的等待时间同样缩短。

### 4. 分块指令与循环调度

Fusion-ISA把一层重复执行的操作组织成指令块。setup同时设定两侧位宽、BitBrick融合方式和数据供给语义，block-end给出后继块地址；块内无需为每次乘加重新配置。表I的常规格式共32位，由5位操作码、6位操作数说明、5位循环标识和16位立即数组成，不同指令复用这些字段。

循环指令描述次数，compute指定乘加或最大值等运算，gen-addr描述各维步长。式(4)将地址写成基址加各循环迭代器与步长的乘积之和，因此能够表示多维数组遍历。评估中的层通常用30—86条指令表达，指令在块开始时取出和译码，再复用已定义的循环语义。片外装载、片上缓冲访问分别使用不同指令，使数据复用与访存调度显式化。

图12的全连接例子把输出保留在较内层计算过程，避免每处理一个输入通道就写回。循环分块使输入、权重和输出片段适配片上容量，重排则改变哪类数据优先复用。作者报告，该例输出片外访问可减少IC倍，片上输出访问减少约tile_ic倍；卷积循环从六重增加到分块后的十二重，增加的指令数由整层执行分摊。

激活与矩阵计算使用不同资源时，还能合并指令块并直接传递结果。解读：软件负责使融合配置、数据布局及循环顺序一致，才能兑现硬件并行度。本文未评估层内位宽变化；作者提出可用多个指令块表达，这仍会引入额外配置与调度边界。

## 4. 实验方法与实验结果

六个CNN覆盖图像、目标和数字识别，LSTM/RNN执行PTB语言建模；表II规模为13—4269Mops、0.5—116.3MB。模型取自已有量化研究，含1/2/4/8位，未另列准确率；AlexNet与ResNet-18采用通道加倍的4位模型，Eyeriss/GPU使用原模型，乘加量约差4倍。

Bit Fusion经45nm Verilog综合、RTL校验和周期仿真，SRAM能耗用CACTI-P建模，无芯片实测。Eyeriss按500MHz、1.1mm²计算逻辑及5.87mm²芯片预算比较，固定16位。图13数值如下：

| 模型 | 加速倍数 | 能耗降低倍数 |
|---|---:|---:|
| AlexNet | 1.9 | 1.5 |
| Cifar-10 | 13.0 | 14.0 |
| LSTM | 2.4 | 4.8 |
| LeNet-5 | 2.7 | 4.3 |
| ResNet-18 | 1.9 | 1.9 |
| RNN | 2.7 | 5.1 |
| SVHN | 8.6 | 10.0 |
| VGG-7 | 7.7 | 9.9 |
| 几何平均 | 3.9 | 5.1 |

Stripes比较对齐45nm、980MHz和存储，每tile以512个融合单元替换4096个SIP；平均加速/能耗降低为2.6/3.9倍，LeNet-5最高5.2/7.8，AlexNet最低1.8/2.7。图10局部单元面积/功耗另降3.5/3.2倍。

默认带宽128位/周期，升至512时正文报告平均快1.6倍，降至32时性能降60%；图15归一化标注、柱高及汇总存在出入。默认批量16；256相对1平均快2.7倍，RNN达21.4倍，64后趋饱和，属于批处理执行收益。

GPU预热1000批、测10000批。Bit Fusion外推到16nm、500MHz，含4096单元、896KB SRAM，面积5.93mm²、估计功耗895mW；相对TX2快16倍，Titan Xp FP32/INT8为12/19倍，Bit Fusion比后者慢约16%；VGG-7对应48/30倍。

局限包括工艺缩放假设，以及GPU的250W属于TDP，不能充当同口径任务能耗。SRAM“等容量”与112/181.5KB列值、VGG-7数据集描述均有口径不清之处；图18 ResNet-18能耗为4.4倍，正文约4倍。
