# MFSA: A Multi-Format Systolic Array with Native Micro Scaling Support 通俗讲解

### 0. 整体创新点通俗解读

解读：可以把MFSA看成一条能处理不同规格货件的流水线。输入通道的宽度固定，大货一次装一件，小货一次装两件、四件或八件；每站仍向下一站交出一份统一格式的总账。DPA把同站的多件货先合计，再统一处理精度和舍入，因此输入越细，重复账务处理被摊薄得越明显。这个类比对应的是算术资源共享，不表示低精度数据保留了高精度信息。

MX像是每箱货附带一个计价单位。朴素方案先结算每箱，再用另一本总账汇总；OBSR让正在传递的账本改用下一箱的单位。单位都是二的整数次幂时，通常只需改指数，就能让后续累加继续复用原有路径。NVFP4的单位带小数系数，因而还要补一次分数乘法，不能仅靠改指数完成。

论文的价值在于把已有融合点积思想推进到完成布线的多格式阵列，并分别量化PE、格式扩展和块尺度支持的成本。类比的边界也很明确：浮点账本容量有限，换单位可能溢出或下溢，不同汇总顺序也会产生不同舍入。真实轨迹支持其实际可用性，对抗测试则说明它没有无条件等价保证；峰值TOPS与阵列能耗也尚不足以说明完整LLM系统收益。

### 1. 融合点积复用

可以把DPA想成一位先收齐同批小票、再统一结账的收银员。若每收到一张小票都把金额四舍五入，某些很小的金额可能提前消失；把几张小票先合在一起，最后统一舍入，有机会保留它们。硬件也能共用结账设备，省去多套重复的规格化和舍入电路。

小票越小，同样宽的输入口一次能送进来的张数越多，所以低精度模式每周期处理更多乘积。但收银员交给下一站的仍是一张FP32总单；下一站还会继续舍入。这个机制节省设备并改变舍入位置，并没有让整条流水线拥有无限精度，也不能自动修复输入量化时已经丢失的信息。

### 2. 块尺度在线换基

想象账本记着“12份，每份8元”，总额就是96元。下一箱商品改用“每份32元”，就先把旧账改写成“3份，每份32元”，再把新箱的2份加进来，得到5份、共160元。OBSR做的就是在箱子交界处更换账本单位，让同一本账继续使用。

单位按二的幂变化时，浮点数通常只要调整指数，不必重算尾数，也不用另开一本总账。但账本能写下的数有上下限：单位突然变化太大，即使实际金额还正常，中间记下的份数也可能超出范围。论文真实模型数据没有遇到这种情况，专门构造的极端数据却遇到了。因此这是一种有条件的便宜换算方式，不能理解为所有输入下都完全等价。

### 3. 整数槽位共享

可以把乘法器看成几种尺寸的工作台。浮点输入虽然占八位，但其中一部分是指数，真正送到乘法工作台的有效数字更短；八位整数却需要工作台处理完整整数。因此，能同时处理四对FP8的资源，并不自动意味着也能同时处理四对INT8。

MFSA让整数借用尺寸足够的浮点工作台，所以增加格式时不用重新建整套计算设备。代价是同样写着八位或四位，整数一次能处理的项数更少。若一间工厂偶尔接整数订单，共用设备比较省；若天天生产整数产品，增加专用工作台可能更合算。论文给出了这笔面积账，但没有把增加工作台后的收益换算成真实模型运行时间。

### 4. 分数尺度分解

原来的OBSR擅长处理“单位翻倍或减半”。NVFP4的单位还带一个小数比例，例如两个尺度的小数部分相乘后得到1.875。只修改“翻了几倍”的记录还不够，计算结果还要乘上这个比例。

论文把两件事分开：整倍的二次幂继续交给指数换算，小数比例交给一个新增乘法器。在同一局部点积里，各项共享这个比例，所以可以先求和，再统一乘一次，减少重复设备。这个阶段能精确完成比例折叠，后面的FP32结账仍然会舍入。新增设备也确实占面积、消耗功率；论文证明其开销低于所比较的另外两种实现，但尚未给出NVFP4运行整模型的速度与准确率。
