# Efficient Precision-Scalable Hardware for Microscaling (MX) Processing in Robotics Learning 通俗讲解

### 0. 整体创新点通俗解读

---

**核心观点**

这篇论文解决的场景是：**机器人要在边缘端做“持续学习”**（on-device training），而不是只做推理。训练对精度的要求远高于推理，但又受限于边缘设备的算力和内存。MX 格式是个折中方案，但现有硬件（对标 SotA 的 Dacapo）只支持 MXINT，且架构上有个很别扭的“向量分组”问题。这篇论文干了两件事：**算术层做一个全能又省料的 MAC**，**架构层把“条形分组”改成“方块分组”**。最终在相同峰值吞吐量下，内存省 51%，有效训练吞吐量提升 4×。

---

**痛点直击**

**痛点一：算术单元的“格式碎片化”**

- MX 标准定义了 6 种格式：MXINT8、两种 MXFP8、两种 MXFP6、MXFP4。它们的 mantissa 长度分别是 1、2、3、8 bit，还混着整数和浮点。
- 如果为每种格式单独搭一套数据通路，硬件面积会爆炸；如果用 1-bit 位级处理单元来堆（如 Flexibit），又**面积和能效都不划算**。
- 更狠的一点：FP 加法对齐问题。MXFP8 E5M2 的指数范围是 ±30，如果老老实实用**整数加法器**去对齐，需要 **78-bit 加法器**——为了加两个 8-bit 数，造一个 78-bit 加法器，这是荒谬的。

**痛点二：架构层的“转置困境”（这是全文最精华的痛点）**

- 反向传播有个绕不开的特性：**权重矩阵既要按行用，又要按列用**（前向是 A×W，反向是 E×Wᵀ）。
- 而 MX 的标准分组是 **32 元素的“向量块”**——要么按行切，要么按列切。
- 这就死锁了：同一份权重，按行量化和按列量化，**得到的共享指数完全不同**。
- 现有方案只有两条烂路：
  - **存两份**：权重存原版 + 转置版，存储直接翻倍（Dacapo 走的就是这条路，Table III 里它要存 W 和 Wᵀ 两份 162.0 KB）；
  - **存 FP32 原版 + 反复重量化**：计算开销和能耗上去了。

**通俗比方**

**关于“转置困境”，打个比方：**

- 想象一个 8×8 的合唱团方阵，每个人手持一个数字卡片。MX 的共享指数就像“给每一排统一发一个扩音器”（向量分组 = 按排分）。
- 前向传播时，评委按**排**打分，没问题；反向传播时，评委突然改按**列**打分——但你按排发的扩音器，按列看就完全错位了。
- 你的选择：要么**把整个方阵重新组织一遍再排练一次**（重量化，浪费算力），要么**雇两个合唱团，一个按排站位、一个按列站位**（存两份，浪费内存）。
- **正方形分组的天才之处**：如果扩音器是发给**整个 8×8 方阵**的（64 人共享一个），那么无论评委按排看还是按列看，看到的分组结构**一模一样**。转置一个正方形块，还是同一个块。**一份存储，两个方向通用**。

**关于“精度可扩展 MAC”，比方是：**

- 与其为 4 种体型的运动员各建一个更衣室，不如建一个**模块化更衣室**——最基本的隔间单元是“2-bit 乘法器”这个乐高积木，一共 16 块：
  - INT8 模式：16 块积木**全部拼起来**，干一次大活（一个 8×8 乘法）；
  - FP8/FP6 模式：拆成 4 组，每组 4 块积木 + 一个小指数加法器，**四路并行**；
  - FP4 模式：8 块积木各自配一个 2-bit 指数加法器，八路并行（受限于带宽，没跑满）。
- 更妙的是“物尽其用”：低精度模式下，**INT 模式才需要的那些对齐加法器被“重新征用”**，反过来去累加 FP 的并行结果——硬件没有一刻是闲着的。

**关键一招**

**第一招：用“26-bit mantissa 加法器 + 2-bit 扩展”替换“78-bit 整数加法器”**

- 作者没有在整数域里硬扛对齐，而是把累加放在 **FP32 域**完成。
- 窄 FP 格式（FP4/FP6/FP8）会产生大量 **subnormal 数**（未归一化输入）。正常思路是加归一化电路——贵。
- 作者的取巧：**只把 mantissa 加法器多扩 2 位**，就足以容纳非归一化输入，直接省掉整套归一化逻辑。Table II 里这个选择直接省下约 43% 面积（3640 → 2078 µm²，配合 bypass 优化）。

**第二招：用“8×8 方块”替换“1×32 向量条”**

- 这是架构层的灵魂操作。注意作者**没有另起炉灶造新标准**，而是在 MX 标准的框架内打了个擦边球：
  - MX 标准规定块大小是 32 的倍数；
  - 作者用 64 = 8×8，即**两个 32 元素块共用一个共享指数**——合规，但形状从“条”变成了“方”。
- 后果链条非常清晰：
  - 方块转置不变 → 反向传播直接复用同一份量化权重；
  - 不需要存 Wᵀ 副本 → **存储省 51%**（Table III：Dacapo 347 KB vs Ours 163 KB）；
  - 不需要反复重量化 → 省下量化算力；
  - PE Array 天然以 8×8 方块为单位吞吐数据 → 数据流干净，摆脱了 Dacapo **systolic array 进出数据搬运的开销**。

**第三招：输出固定（output-stationary）+ 共享指数前置**

- 部分和**留在 PE 内部累加**，避免 FP32 中间结果在片上乱跑；
- 两个输入方块的共享指数在 PE 级先加好，直接**施加在 L2 加法器输出上**，指数处理对数据通路几乎零侵入——Fig. 7 显示共享 exponent 的能耗占比**可以忽略不计**。

---

**最后看结果，为什么“4× 吞吐提升”是真的赚**

- 两者在 **iso-peak-throughput**（同样 4096 个 MAC、同样 400MHz、同样 TSMC 16nm）下对比：

| 指标 | Ours | Dacapo | 差距 |
|---|---|---|---|
| 内存 [KB] | 179.78 | 370.13 | **省 51%** |
| 训练延迟/batch (MXINT8) [µs] | 13.575 | 50.5 | **3.7× 快** |
| 训练延迟/batch (MXFP8) [µs] | 6.03 | 30.7 | **5.1× 快** |
| 能耗/OP (MXFP8) [pJ] | 1.92–2.12 | 1.46 | 慢 1.3–1.45× |

- 表面上“峰值吞吐量”相同，但 Dacapo 的 systolic 脉动阵列要把数据**一遍遍移进移出**，有效吞吐大打折扣；加上它还得处理两份权重的量化开销。
- 唯一让步是 MXFP8 模式下能效略高（约 1.3–1.45×），但在 Fig. 8 的真实训练曲线里，MXFP8 用更少时间收敛，**时间维度和能量维度上的实际赢家依然是它**。

一句话总结：**这篇论文的本质，是把 MX 格式里“一维的条”扭成了“二维的方”，让反向传播的转置操作变成“免费”的；再配上一个乐高化的全能 MAC，把标准里所有格式一网打尽。** 两个创新单看都不惊天动地，但组合起来正好卡住了边缘端机器人持续学习的命门——内存和有效吞吐。

### 1. Precision-Scalable MX MAC Unit (支持全部六种MX格式的统一INT/FP算术单元)

**痛点直击**

- MX 标准一口气定义了**六种数据格式**（MXINT8、两种 MXFP8、两种 MXFP6、MXFP4），mantissa 长度从 1 bit 到 8 bit 不等，还混着整数和浮点。
- 这对硬件设计者是个噩梦：传统做法要么**为每种精度单独做一套 datapath**（面积爆炸），要么用 **1-bit 串行的 bit-level 处理单元**（像 FlexiBit 那样），灵活是灵活，但每个 bit 都要过一遍进位传播，**能量和延迟都很难看**。
- 更阴险的一个坑：**MXFP8 (E5M2) 的 exponent 范围高达 ±30**，如果老老实实用整数加法器做精确累加，一个加法器要做 **78 bit 宽**——为了区区 8-bit 数据格式，付出 78-bit 加法器的代价，这在边缘设备上是不可接受的。
- Dacapo 作为 SotA 训练处理器，只支持 MXINT 这条腿，**根本没摸到 MX 标准的 FP 家族**。这就是“顾头不顾尾”：推理时 INT8 很香，但训练时梯度需要 FP 精度，硬件却给不了。

---

**通俗比方**

- 把这个 MAC 单元想象成一个**乐高拼装车间**：它有 **16 个 2-bit 乘法器**作为标准砖块。
  - 干 **INT8** 的大活时，16 块砖**全部拼在一起**，拼成一个 8×8 的大乘法器；
  - 干 **FP8/FP6** 时，拆成 **4 组、每组 4 块砖**，每组负责一个乘法，各配一个小小的 exponent adder；
  - 干 **FP4** 时，每个 2-bit 乘法器自己就是一个完整乘法器，配个 2-bit exponent adder 就能单飞，**8 路并行**。
- 关键的“一鱼两吃”在于：**低精度模式下多出来的乘法器没闲着**。INT8 模式需要 16 块砖，FP8 只需要 16 块，但 FP4 模式下有很多乘法资源被“释放”了——这些**冗余的加法/移位逻辑被重新征用**，去做 partial product 的求和（L1/L2 层级累加器）。
- 这就像搬家时把书柜拆了，**拆下来的木板正好拿来当桌腿**——不买新家具，功能照全。

---

**关键一招**

作者没有为六种格式造六个单元，而是做了两个巧妙的“逻辑扭转”：

- **把“乘法器”的最小颗粒度从 1-bit 提到 2-bit**：
  - 任何 mantissa 长度（1、2、3、8 bit）都能被 2-bit 单元** tiled 出来**，进位链长度可控，比 bit-serial 高效得多。
- **用“共享 exponent”这个 MX 天然属性来砍掉巨大加法器**：
  - 既然一个 block 内 32 个元素共享一个 exponent，那么**对齐操作大部分被数据格式本身吸收了**，L2 累加器不需要 78-bit 整数加法，只需一个 **FP32 加法器 + 26-bit mantissa adder**。
  - 针对窄 FP 格式里常见的 **subnormal 数**，作者没上昂贵的 normalization 电路，而是**简单粗暴地把 mantissa 加法器加宽 2 bit**——Table II 显示这一招比 normalize 输入省了 **36% 面积**（3640 → 2341 µm²），能量几乎减半。
- **用 mode-specific bypass 平衡 critical path**：
  - INT8 和 FP4 的瓶颈在 L1 adder，FP8/FP6 的瓶颈在 L2 的 alignment 逻辑；
  - 前两种模式**直接绕过** L2 alignment，让综合工具不用为最坏路径全局加强驱动，又省了约 11% 面积（2341 → 2078 µm²）。

**一句话总结**：用 **2-bit 乘法器做乐高底座**实现精度可缩放，用 **MX 的共享 exponent 兜底**消灭巨大对齐加法器，再把缩放后**闲置的硬件复用为累加器**——三招合起来，一个单元通吃六种格式，面积和能量都还打平甚至优于专用设计。

### 2. Square-based MX PE Array and GeMM Core (64元素方形共享指数块架构)

**痛点直击**

- 先看清楚 MX 格式的本质：**32个元素共享一个 exponent（scale）**。这是个“分组打包”的方案，一行（或一列）32个数，共用一个“量级标签”。
- 麻烦出在**训练**上，尤其是 **backpropagation**：
  - Forward pass 做 GeMM 时，权重矩阵 W 用的是“**行方向**”的 dot-product；
  - Backward pass 算梯度时，需要的是 W 的转置 Wᵀ，即“**列方向**”的 dot-product；
  - 关键矛盾：对矩阵按**行**切 32 个一组做量化，和按**列**切 32 个一组做量化，得到的**共享 exponent 完全不同**。
- 所以之前的做法（包括 SotA 的 Dacapo）只有两条难受的路：
  - **存两份权重**：一份按行量化、一份按列量化 → **内存直接翻倍**，对边缘设备是致命的；
  - **存 FP32 原始权重**，每次反向传播时**现场重新量化** → 反复量化，算力和能耗白白烧掉。
- 这就是典型的“顾头不顾尾”：解决了正向的高效，反向传播就变贵。

---

**通俗比方**

- 想象你有一张**大幅Excel表格**，为了压缩存储，你决定每 32 个格子共享一个“倍率系数”。
- 如果你**按行**压缩一遍、**按列**压缩一遍，会发现两份压缩结果对不上——因为同一格数字在行里和列里所处的“量级邻居”不同，分到的共享倍率就不一样。
- 作者的解法朴素到近乎“反常识”：**把压缩单位从“一条线”变成“一个方块”**。
  - 8×8 = 64 个格子的方块，**整块共用一个 exponent**；
  - 你把这个方块**横着看**是一个块，**竖着看**还是同一个块；
  - 就像一个**方形集装箱**——无论你从哪个方向装卸货，箱子的尺寸和标签都不变。
- 这里的“顿悟点”是：**转置矩阵对方阵块是不变量（invariant）**。Wᵀ 里的那个 8×8 块，转置之后还是那 64 个数、还是那个共享 exponent，只是行列排布换了一下。一份存储，正向反向通吃。

**关键一招**

- 作者并没有去优化“量化器”本身，而是**扭转了“分组”的几何形状**：把 **32 元素的 vector block 替换为 64 元素（8×8）的 square block**。
- 具体的逻辑链条是这样的：
  - **量化粒度改变**：不再按行/列切 32 个，而是取 8×8 的方块，两个 32 元素块共享同一个 E8M0 exponent——保持了与 **MX 标准**的兼容性（块大小是 32 的倍数）；
  - **对称性红利**：因为方块在转置下不变，**backpropagation 不再需要 requantization**，也**不需要第二份转置权重**；
  - **存储收益**：对比 Dacapo 的双份量化存储，权重内存直接**砍掉约 51%**（3.94× vs FP32，而 Dacapo 只有 1.91× 左右，见 Table III）；
  - **架构顺势而为**：PE Array 的设计跟着块形状走——64 个 precision-scalable MAC 排成对应结构，一次吃进两个 8×8 方块做乘法：
    - **INT8 模式**：8 个 cycle 处理一个块乘法；
    - **FP8/FP6 模式**：2 个 cycle（利用 4 路并行 FP 通道）；
    - **FP4 模式**：1 个 cycle（8 路并行）；
  - **GeMM Core 布局**：4×16 的 PE Array 网格，高度 4 对应 batch size 32 ÷ 8（方块维度），宽度 16 平衡带宽与并行度——专门为边缘端训练的**小 batch**场景调优；
  - **output-stationary dataflow**：部分和在 PE 内部本地累积（FP32），两个输入方块的共享 exponent 在 PE 级相加后，统一作用于 L2 adder 输出，避免中间结果反复搬运。

**一句话总结**：这是一个“**用几何对称性换存储和算力**”的招——作者发现训练中“正向用行、反向用列”的矛盾，本质上源于 vector 分组的不对称，于是把分组单位做成**转置不变的方块**，一份量化权重就同时服务所有训练 pass，存储减半、requantization 归零，而 PE Array 只是把数据流按方块形状重新组织了一遍。
