# FuseDot: A Multiplication-Fused Dot Product Accelerator for Efficient LLM Inference 通俗讲解

### 0. 整体创新点通俗解读

可以把点积想成结算一张很长的购物清单：每行都有一个数量和一个单价，传统做法逐行计算金额，再把金额相加。如果清单有128行，却只有16种单价，就可以先把相同单价的数量合并，最后只做16次乘价。FuseDot中的激活对应数量，量化权重对应单价，MFDP就是这种先合并、后乘价的计算方式。

真正困难的是同时结算许多张清单。每个输出列的单价分布不同，对应的合并方式也不同。IndexMM为每张清单保存位置表，让计算单元按表取数；激活本身仍共享存放。由于货架分成4个读取区域，多张位置表可能同时指向同一区域，DualReorder便提前调整清单内部的处理顺序，让并行请求尽量分散。

合并之后，负责乘价的设备不必每个工位各放一台。CoShare让不同工位错开提交，并按固定间隔连接共享乘法器，再用队列容纳短时集中请求。SymHalf则利用正负同幅值的关系，把一部分数量先相减，继续减少乘法。这些安排共同决定节约下来的乘法器面积能否用于增加并行工位。

类比的边界也很明确：激活可以是负数和浮点数，量化组之间的单价表及缩放参数可能不同；调整浮点求和顺序还可能改变舍入。位置表、读取端口和排队都需要硬件成本，不能把乘法减少八倍直接理解成推理加速八倍。

解读：论文提供了从代数重组到存储访问、共享执行的连贯方案，4位PPL一致及等面积比较支持其可行性。当前证据来自仿真和物理设计工具，并集中在批量128；索引开销、小批量表现、不同量化格式支持，以及浮点误差范围仍需要更完整的实验说明。

### 1. 按类融合点积

假设要算许多包商品的总价。传统方法是每包数量乘单价，再把金额相加。如果很多包的单价一样，可以先把这些包的数量加起来，最后只乘一次单价。FuseDot利用的正是低位权重只有少数取值这一特点。

例如128项计算只有16种权重，最多做16次乘法就够了。不过，128个激活仍然需要读出并归类、相加，所以整体工作不会自动缩小到原来的八分之一。省下的主要是昂贵的乘法设备及其使用次数。

这里还有两个边界。第一，不同量化组可能使用不同缩放规则，相同编号未必代表相同实际数值，合并要遵守组边界。第二，计算机里的浮点加法有舍入，先加谁、后加谁可能产生微小差别。论文报告的困惑度一致说明已测任务质量保持住了，但不能把它理解成每一步计算都完全相同。

### 2. 索引驱动取数

把激活矩阵想成公共书架，每个输出列都要按自己的规则挑书。有的列需要先拿第0、2本，再拿第1、3本；另一列的顺序可能不同。若为每一列复制一套书，书架很快就放不下。

IndexMM给每个输出列一张取书单，记录书的位置和每一组要拿几本。书仍放在公共书架上，工作人员照单取书；拿够一组，就把这一组的结果交给下一道计算。这样，同一份激活可以服务许多不同的权重列。

代价是取书单也占空间，而且查位置、走到对应区域都需要时间。如果四个人同时要从同一个只有一个服务口的区域取书，仍然得排队。所以索引解决了“怎样表达不同分类”的问题，后续重排还要解决“怎样同时取数”。离线写好清单并不意味着运行时没有读取清单和安排访问的成本。

### 3. 双阶段冲突重排

想象四个人同时到四个服务窗口办事，每人都有几组可以调整顺序的任务。如果四个人当前这一组都集中需要窗口0和2，那么只在组内换顺序，窗口1还是闲着，拥堵很难消除。

DualReorder先做较大的调整：为每个人挑选先办哪一组，让四个人合起来对各窗口的需求更均衡。它不会把所有组合都试完，而是两两比较，只留下少数较好的方案，再逐步合并。

接着处理每一轮的具体选择：可选窗口最少的人先选；后面的人尽量避开已经占用的窗口。实在避不开，就接受一次排队。这种方法快，也确实让多数访问不再冲突，但保留少数候选和逐步贪心都可能错过更好的方案。图中的四人四窗口可以完全错开，真实4位实验则仍有部分冲突行，不能把示例当成普遍保证。

### 4. 列共享与对称合并

许多工位先把同类数据加起来，偶尔才需要计算器做一次乘法，于是可以共用计算器。但如果所有工位同时完成，计算器前就会排长队。FuseDot让任务逐站传递，使工位错开完成，再把相隔一定距离的工位接到同一台计算器上。

队列负责吸收短时集中到来的任务。队列多大，依据的是这套流水中最多有多少类别、相邻任务怎样交叠；“平均任务少”本身并不能保证永远不堵。

SymHalf像把同单价的收入和退款先抵消：原来分别乘正价、负价，现在先做数量差，再乘一次公共价格。它要求正负价格确实成对、幅值相同。若价目表本来不对称，就不能照搬。因此，共享乘法器需要有组织的到达顺序，对称合并也需要符合条件的量化表示；两者都不是单纯删掉一半硬件就能完成。
