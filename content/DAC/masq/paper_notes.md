# MASQ: Accelerating Masked Diffusion via Stage-Wise Multi-Precision Quantization 论文解析

## 0. 论文基本信息

**作者 (Authors)**: Seeyeon Kim, Jaehun Lee, Sungyeob Yoo, Joo-Young Kim

**发表期刊/会议 (Journal/Conference)**: DAC 2026

**发表年份 (Publication Year)**: 2026

**研究机构 (Affiliations)**: KAIST, Daejeon, Republic of Korea

---

## 1. 摘要

MASQ 是 DAC 2026 的掩码扩散软硬件协同设计。修复或编辑任务只有部分图像需要改变，但 U-Net 的卷积和注意力仍会处理全图。论文利用区域重要性差异，将核心编辑区保留在 MXINT8，把空间较远、语义关联较弱的区域逐步降低至 MXINT4/2，同时继续保留必要上下文计算。

算法由四部分组成：按卷积感受野膨胀掩码、按注意力关联提升重要 token、按去噪时间步降低部分阶段精度，以及调整归一化和 softmax 以减小跨区域误差传播。硬件以二比特位片串行处理激活，权重保持八比特，用 32 元素共享指数块执行混合精度计算；掩码管理器负责膨胀、语义更新和跨分辨率下采样。

论文评估 Stable Diffusion v1 修复与 SDEdit 编辑，采用 RTL 综合、周期精确模拟及 GPU 基线比较。相对 A100/Orin NX，最高分别为 16.06×/5.39× 加速和 4.18×/4.93× 能效；这些最大值出现在不同任务与基线条件下。与同硬件统一 MXINT8 相比，算法增量小于这些整机对比数字。

质量总体接近 FP16，但 FID 等部分指标有所下降。面积/功耗来自 14nm、800MHz、0.8V 的综合配置，尚不能视作流片芯片的实测表现。

## 2. 背景知识与核心贡献

### 掩码任务为何仍然很贵

去噪每一步只在掩码区保留生成结果，未掩码区会重新注入当前时间步噪声后恢复原图上下文。但网络中的卷积感受野、注意力和归一化把不同区域联系起来，所以 U-Net 仍对完整特征张量执行。直接忽略未编辑区域会破坏边界连贯性与远程语义关联。

缓存式 SIGE 可以复用特定参考图像的中间特征，但需要预先生成并保存各时间步特征。论文给出的 512×512 Stable Diffusion 示例中，FP16 权重为 1.72GB，50 步缓存约 12.31GB。MASQ 面向直接给定图像和掩码的场景，用更低精度执行部分上下文，避免依赖这批预生成特征。

### 空间重要性之外还有什么

单纯把掩码内设为高精度、外部设为低精度，会让边界附近量化噪声经卷积传播，也会让远距离重要 token 经注意力影响编辑区。论文因此保留四个阶段标签：核心区、按当前分辨率卷积深度扩展的邻近区、考虑更低分辨率感受野的外圈，以及其余区域。语义细化再选择性提升部分远处 token。

### 数值格式与算术结构如何配合

每块 32 个整数共享一个八比特指数，激活使用 MXINT8/4/2，权重均为 MXINT8。二比特位片宽度固定，激活精度决定串行周期数，避免为三种精度分别复制整套乘法器。块指数在定点点积结果转回 BF16 时应用，跨块累加使用 FP32。

设计还照顾矩阵之外的计算：组归一化只用 Stage 2–3 统计量，softmax 对 Stage 0 设零概率。虽然非矩阵运算只占少量算术数量，却能全局传播误差；硬件评估中 VPU 功耗也不能忽略。

## 3. 核心技术和实现细节

### 0. 技术架构概览

输入图像与二值掩码进入系统后，掩码膨胀器根据 U-Net 的卷积深度生成四阶段标签。下采样器为不同分辨率生成对应掩码，语义更新器根据注意力概率细化部分 Stage 0。控制器结合当前去噪时间步，将阶段标签映射到 MXINT8/4/2。

激活经过量化器转换为 32 元素共享指数块；一组 32 个激活广播到同一 MP-MPU 的 32 个 BMPE，每个 BMPE 接收自己的 32 个权重。因此当前周期各 BMPE 使用统一 type/cfg，掩码阶段通过控制执行批次来作用于计算，而不是让每个 BMPE 随机进入不同长度的串行任务。

每个 BMPE 含 32 个二比特激活×八比特权重的符号感知乘法器。INT8/INT4/INT2 激活分别拆成四、二、一片，从高位开始处理，前一结果左移两位后加入当前片结果。最高片包含符号位，后续低位片应按其真实数值权重解释。定点局部和恢复块指数后转换为 BF16，再进入 FP32 累加，最终以 BF16 输出。

VPU 执行归一化、softmax、激活和逐元素操作，片上存储保存权重、激活、中间特征、掩码，DMA 与外存交互。完成当前去噪步后，调度器推进时间步，部分阶段降低精度，主掩码区仍保持八比特。

### 1. 感受野膨胀与四阶段精度

卷积让掩码区与邻近上下文互相影响，单一内外二分会把边界外的量化噪声带回重点区域。MASQ 的 Stage 3 是主掩码，Stage 2 按当前分辨率 3×3 卷积层数膨胀，Stage 1 考虑下一低分辨率层级更大的感受野，Stage 0 是其余区域。

例如连续两层 3×3 卷积，空间依赖半径扩展两个 token，包括对角方向；更低分辨率的同一距离映射回当前尺度要加倍。多级标签保留区域身份，使早、中、晚阶段即使暂时使用相同位宽，也能在后续分别调度。

主区始终八比特，其他区按 8/8/4/2、8/4/4/2、8/4/2/2 三套方案变化。它没有省去全部背景卷积，效率来自减少部分激活串行位片数。掩码管理只占很小硬件比例，但其带来的算法准确性依赖感受野和调度点设置是否适合当前模型。

### 2. 注意力细化与全局误差控制

空间远并不意味着语义不重要。MASQ 在最后一个自注意力层，根据 token 与掩码 token 的平均注意力概率，将超过阈值的 Stage 0 token 提升到 Stage 1。初期使用八/四比特计算概率，实验每五步细化一次，从而让语义分配随去噪演化。

归一化与 softmax 也会传播误差。组归一化只由 Stage 2–3 token 计算均值、方差，再应用于全部 token，避免粗精度背景污染共享统计量。注意力 softmax 则排除 Stage 0，令其概率为零。

这些操作改变了原网络的计算语义，需要用质量实验验证。规则按阶段描述，不能仅凭位宽自行把所有 INT2 token 都屏蔽，因为后期 Stage 1 也可变成 INT2。语义阈值和精度分配决定速度与质量取舍，论文所测成功不代表任意阈值都有效。

### 3. 二比特位串行与有符号重建

同一个 BMPE 并行计算 32 对二比特激活与八比特权重。八、四比特激活按高到低拆成四、二片，对前一部分和左移两位，再加当前片乘积。type 指定总精度，cfg 指定当前位片；SAM 识别是否包含符号位，避免把低位片也当作独立有符号数。

解读算例：四比特补码激活 -3 为 1101，高片 11 表示 -1，低片 01 表示 +1。若权重为 5，先得到 -5，再左移两位并加 5，结果为 -15。若把高片误当 +3 或把所有片都按相同符号规则处理，就无法得到正确结果。

点积在定点寄存器重建，随后结合激活与权重的共享指数转为 BF16，再作 FP32 累加，最后输出 BF16。8/4/2 激活需要 4/2/1 周期，不等于整层延迟必然按 4/2/1 缩放，因为数据搬运、非矩阵计算和多阶段区域占比仍有影响。

### 4. 掩码管理与统一精度广播

一个 MP-MPU 的 32 个 BMPE 接收同一组 32 激活，各自配不同的 32 权重，在当前周期共享同一 type/cfg。这样的组织避免同一广播计算批次的精度和串行长度分歧。论文的掩码感知能力来自控制器组织这些批次，而不是每个乘法器任意独立切换。

掩码由两比特编码四阶段。膨胀器用行位移、左右 OR 和相邻行 OR 扩展空间范围，支持最大 64×64 tile，更大掩码分块处理。更新器将二值语义细化掩码与 Stage 0 合并，选择性提升到 Stage 1。下采样器用步长二的 2×2 窗口，两个或更多输入位为一便输出一，平票也算一，不能实现成严格三票多数。

这些轻量逻辑把软件的重要性判断转为可执行元数据。表 2 中掩码管理与量化器合计仅 0.07mm²、0.12W，但实际大掩码分块边界的依赖、存储供给和任务调度仍需实现正确。

## 4. 实验方法与实验结果

### 任务、掩码和调度

| 任务/数据集 | 平均掩码占比 | 用途 |
| --- | --- | --- |
| Stable Diffusion v1 / EditBench | 42.87% | 文本引导修复 |
| Stable Diffusion v1 / LAION 修复集 | 2.38% | 较小区域修复 |
| SDEdit / LSUN Church | 13.12% | 笔画引导编辑 |

总计 50 个去噪时间步，每五步执行语义细化，第 9、18 步分别降级配置。由 Stage 3 到 0 的精度依次为 8/8/4/2 → 8/4/4/2 → 8/4/2/2，主掩码一直为八比特。

### 速度与能效的基线要分别看

| 对比 GPU | 任务 | 统一 MXINT8 / MASQ 加速 | 统一 MXINT8 / MASQ 能效 |
| --- | --- | --- | --- |
| A100 | EditBench | 6.76× / 8.19× | 2.32× / 2.76× |
| A100 | LAION | 6.76× / 11.13× | 2.32× / 3.69× |
| A100 | LSUN | 8.10× / 16.06× | 2.24× / 4.18× |
| Orin NX | EditBench | 2.94× / 3.65× | 2.20× / 2.71× |
| Orin NX | LAION | 2.94× / 5.27× | 2.20× / 3.89× |
| Orin NX | LSUN | 2.48× / 5.39× | 2.30× / 4.93× |

相对同硬件统一 MXINT8，服务器平均速度/能效再提升 61.35%/54.88%，边缘平均再提升 73.58%/71.45%。与 EXION 的延迟比较使用对方原文数据；MASQ 在 EB/LAION 上相对 EXION 再降 14.5%/37.1%，不是相对 A100 降这么多。

### 质量是接近而非每项改善

表 1 的 EditBench FID 从 167.35 到 168.73，PSNR 从 12.81 到 12.58；LAION FID 从 13.60 到 14.07；LSUN FID 从 19.29 到 20.91，均为下降方向。IS、CLIP 等部分指标略升。应表述为整体质量接近 FP16，不能把原文“保持质量”扩展为逐项无损。IS 的 ± 数值也不能直接当作其他指标差异的显著性证明。

### 硬件条件与解释边界

RTL 采用 14nm，800MHz、0.8V 综合，性能与能耗用周期精确模拟器评估；DRAM 能量来自厂商规格。系统模拟按 MXINT8×MXINT8 峰值匹配 GPU FP16 峰值：A100 312TFLOPS、Orin NX 3.76TFLOPS，外存分别为 2TB/s HBM2E、102.4GB/s LPDDR5。

表 2 的综合配置含 32 个 MP-MPU，每个含 32 个 BMPE，以及 2MiB 片上存储，总计 6.15mm²、5.68W。MP-MPU 为 1.91mm²/2.29W，VPU 为 1.27mm²/2.14W，掩码管理和量化器为 0.07mm²/0.12W。片上存储面积 2.28mm²，按表中数值是最大单项面积；VPU 功耗也接近矩阵单元，说明低运算占比不等于低实现成本。

这组面积配置与峰值匹配的系统模拟条件应分别记录，不应直接宣称一颗 6.15mm² 的实测芯片比 A100 快 16.06 倍。阈值、调度点和质量收益还受模型、掩码比例与任务分布影响；论文没有给出所有新模型上的通用保证。
