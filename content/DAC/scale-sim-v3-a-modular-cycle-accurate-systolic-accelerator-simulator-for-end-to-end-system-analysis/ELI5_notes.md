# SCALE-Sim v3: A modular cycle-accurate systolic accelerator simulator for end-to-end system analysis 通俗讲解

### 0. 整体创新点通俗解读

只看乘法机器速度，可能漏掉等数据的时间。SCALE-Sim v3把工厂里的多组机器、共享仓库、外部运输队列、小仓库冲突和用电量都纳入模型。某种排班计算快，但运输方式差，实际完成反而慢；大机器时间短，也可能耗电更多。

稀疏计算相当于跳过零任务，但要附带位置说明，说明本身也占存储。更多内存通道可加快运输，却不一定帮到小任务。更多bank可让不同机器从不同仓库口同时取货，但总带宽和端口仍有限。

这些是研究仿真工具给出的估计，不是把任意硬件全部行为自动建模。需要输入合适的架构、稀疏格式、存储配置和能量描述，并对关键结论验证。

### 1. 多核时空分区、共享L2与异构负载

把大矩阵任务分给多组机器，可以按输出区域分，也可以把归约工作分成时间段。不同方法需要重复搬的数据不同。同一行机器用同一份输入，就可放在公共仓库；离主存远的机器适当少分任务，避免最后大家等它。

### 2. 结构化稀疏、压缩表示与元数据

只做非零乘法可以省工作，但必须记住每个数原来在哪儿。压缩文件因此包含数值和位置标签，标签不能忽略。更稀疏通常更省存储，但数据怎么送进阵列仍影响真正耗时。

### 3. Ramulator与有限请求队列

外部存储不是随叫随到，运输请求也有排队位置。队列太小，新请求无法发出，机器会饿数据。Ramulator先算每次运输何时完成，再让阵列按真实到达时间推进，所以能发现只算乘法时漏掉的等待。

### 4. 片上布局与bank端口冲突

总共有很多取货口，不表示每次都能同时取到货。如果大家要的数据恰好都在同一个小仓库，仍得排队。布局决定数据放哪儿，bank端口决定每次能取多少，最拥堵的仓库决定这一拍要等多久。

### 5. Accelergy动作计数与能量估计

用电量不只看机器有没有运行，还看这次是取新数据、重复取同一块、空闲还是关时钟。工具先数清各种动作，再按每种动作价格算电费。这样才能比较“更快却更费电”的大阵列和较小设备。
