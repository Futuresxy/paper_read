## 1. 摘要

SCALE-Sim v3 在已有脉动阵列周期仿真上增加五类功能：多核时空分区与共享L2、结构化稀疏矩阵乘法、Ramulator主存延迟及有限请求队列、片上多bank数据布局，以及Accelergy动作计数能耗。它旨在把计算周期与真实供数停顿、能量共同评估，使架构选择不只依赖理想算力。

案例显示，忽略DRAM时WS在六个ResNet-18层计算周期低21%，计入DRAM后OS总周期反而低30.1%；ViT-base的128×128阵列比32×32延迟快6.53倍，但32×32能耗低约2.86倍。结果是配置依赖的仿真结论，部分原文表格存在数值一致性问题，需核对原始实验。

## 2. 背景知识与核心贡献

脉动阵列的尺寸、数据流、存储容量和多核分区共同决定利用率。v2支持IS/WS/OS、双缓冲和访问迹线，但对现代稀疏、多核异构、主存排队、SRAM bank冲突及能耗分析支持不足。仅固定带宽或理想数据可用假设，可能选出在真实内存系统里更差的设计。

v3保留周期级需求/访问迹线作为共同基础，对不同系统模块使用专门模型。Ramulator处理片外DRAM控制和往返延迟，布局模型处理片上SRAM冲突，Accelergy将动作与每动作能量结合；这三者职责不同，不能混为一个带宽参数。

## 3. 核心技术和实现细节

### 0. 技术架构概览

输入为工作负载拓扑、阵列/内存/数据流配置。多核模块决定各核计算及共享存储分区，稀疏模块生成压缩操作数和需求矩阵；访问迹线送Ramulator取得实际延迟，再以有限队列回放修正阵列停顿。片上布局按张量行/列/bank及端口约束计算供数等待。

同一周期迹线还产生MAC、RF、SRAM等动作计数，YAML生成器将高层配置转成Accelergy组件描述与能量表。最终报告聚合周期、带宽、停顿、利用率及能耗，以支持延迟/能量/EDP的不同目标。各模块增加精细度也带来仿真时间开销。

### 1. 多核时空分区、共享L2与异构负载

Sr、Sc为空间映射维，T为时间维，不同IS/WS/OS对应GEMM的M/N/K映射不同。v3允许空间—空间或空间—时间分区；Pr×Pc决定核数，不同切法改变流水长度、重复数据和跨核部分和。分区优化需同时比较周期和内存，而非选择更低某一轴。

同一核行共享输入、同一核列共享权重，通过L2避免各L1重复存储。模型还支持不同阵列/SIMD和自定义向量延迟，按NoP延迟给远端较少负载、近端较多负载。系统互连和同步仍依赖用户配置，不能把共享L2视为免费。

### 2. 结构化稀疏、压缩表示与元数据

支持逐层和逐行N:M，其中N为每M个元素的非零数。CSR、CSC、Blocked ELLPACK描述压缩数据；本文实验采用Blocked ELLPACK及WS，修改操作数/IFMAP需求以匹配非零权重，并报告压缩filter与位置元数据成本。

稀疏不是按比例减少全部执行时间：位置选择、供数、内存容量和停顿也改变。正文称实现限制N≤M/2，但图7包含3:4对照，应区分比较与支持设置；第IV-B的N−M零行表述按组大小应理解为M−N。固定2:4和灵活N:M分别用相应参考硬件验证。

### 3. Ramulator与有限请求队列

先生成带周期、地址、读写类型的迹线；Ramulator在指定技术、rank、通道、频率下计算往返延迟、行缓冲和bank状态；再回放到SCALE-Sim，以读写队列容量和数据到达时间修正阵列停顿。读请求收到数据后清除，写请求在控制器记录后清除。

队列满会阻止继续请求，数据未到不能启动对应阵列计算。队列深度、访问分布和通道数共同决定收益。该片外模型与片上bank布局分离，避免把两类冲突简单合成固定延迟。

### 4. 片上布局与bank端口冲突

多bank内存抽象为二维阵列，行间/行内维度顺序用嵌套循环定义。每个需求元素映射到line、col和bank，对每周期各bank需要访问的不同条目计数。供数延迟由最拥挤bank所需访问数除以可并发端口、向上取整决定，即max_i ceil(rows_i/ports_i)。

固定总带宽也可能因布局冲突而产生不同停顿，增加bank通常提高访问灵活性。原解析把max误成sum，现已按PDF恢复。图12/13刻度存在负值，不能直接将图中slowdown值当成倍数比引用。

### 5. Accelergy动作计数与能量估计

自动YAML以阵列、SRAM、数据流配置结合基础组件模板，产生能量参考表。周期迹线区分重复/随机读写及idle，MAC区分新数据、常量、门控；RF读写依输入/权重/输出驻留改变。动作数乘单次动作能量并计静态耗能，和周期报告聚合。

更大阵列可能延迟低但利用率差、漏电高；因此最优延迟、最优能量、最优EDP可以对应不同规模。插件单次能量、数据宽度、工艺及门控假设决定精度，验证样例不保证所有架构恒定误差。

## 4. 实验方法与实验结果

多核探索GEMM维度M/N/K∈{1000,5000,10000}共27工作负载，阵列边长8/16/32、核数16/32/64，比较计算优化和存储优化分区。稀疏案例以WS与Blocked ELLPACK为主，计入压缩权重和元数据；在250000周期约束下，文中密集ResNet-18需3MB、2:4稀疏768KB。

主存案例TPU类配置，DDR4每通道4Gb、2400MHz，默认读写队列各128项。32→128项平均总周期改善3.76倍，再到512项改善38%；通道1→8对前层更有益，部分后层两通道即饱和。不同bank布局在固定带宽下可显著改变停顿。

验证：固定2:4与Sparse Tensor Core报告一致，Vegeta2:4/1:4 RTL误差≤5%；65nm能量对Eyeriss/8×8阵列PnR偏差4.6%/4.8%。各状态示例误差2.4%、−2.3%、4.3%。相对v2平均仿真时间比，多核2.29、稀疏2:4为0.42、1:4为0.29、能耗1.19、Ramulator2.13、布局16.03，不能把这些比值都称为加速器性能。

原文表V部分EDP不等于延迟×能量：ViT32×32应约4,903,569.4而表中为490356.9；RCNN若干项也有数量级问题。表VI的WS/IS延迟与能量比乘积为约0.798，与正文关于IS的EDP优势措辞亦需核实。翻译保留原文并标注，定量结论应以原始迹线重新计算。
