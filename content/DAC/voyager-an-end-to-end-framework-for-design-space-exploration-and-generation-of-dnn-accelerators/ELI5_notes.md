# Voyager: An End-to-End Framework for Design-Space Exploration and Generation of DNN Accelerators 通俗讲解

### 0. 整体创新点通俗解读

Voyager像一套能按需求造计算设备、同时自动写运行方案的工具。先选计算阵列大小、仓库大小、数字格式和量化方式，模板生成硬件；再把PyTorch模型翻译成它的指令，决定分块、搬数据和融合工序。

同样的模型可以生成不同设备，比较准确率、面积与运行时间。微缩放给一小块数字共享缩放因子，减少低精度误差，但增加存储和控制；因此不能只看每个数字用了几位。Voyager用与硬件一致的C++计算评估这些选择，而不只在浮点模型里模拟舍入。

矩阵单元擅长大乘法，向量单元处理激活、归一化等。把相邻工序融合可减少中间写回；如果向量工序拖慢矩阵，可以增加双缓冲让两者独立推进。最终仍需综合、仿真和物理实现评估，生成框架并不能免除所有硬件验证。

### 1. 硬件模板与矩阵向量协同

矩阵单元像大量乘法机器，向量单元完成后续加工。直接连接省搬运，但后续慢时会堵前面；增加两块交替仓库，让前面先做下一批。深度卷积不适合普通阵列时，可以加专用小工位。

### 2. 类型模板与微缩放硬件

同一台模板机器可以按类型造出不同版本。微缩放给一组小数字附一个公共刻度，算完这一组再恢复刻度、合并其他组。它让小数字更准确，却需要刻度存储和处理，因此要实际比较整个设备。

### 3. 编译器融合与硬件IR

编译器先看模型要做哪些工序，再按机器支持的顺序合并。卷积后紧接ReLU可以直接加工，转置可以在取数据时改变读取顺序，而不先复制一整份数据。IR就是注明形状、位置和格式的工作单。

### 4. 调度模型、HLS编码与证据边界

调度要考虑机器加工多久、数据运来多久，两者能重叠时看较慢的一项。写给HLS的循环方式也会影响它造出的电路。比较不同设备还要说明是否把仓库、后处理和布线面积算进去，否则数字看似相同，含义可能不同。
