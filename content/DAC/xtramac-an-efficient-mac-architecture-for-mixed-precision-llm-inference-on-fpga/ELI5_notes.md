# XtraMAC: An Efficient MAC Architecture for Mixed-Precision LLM Inference on FPGA 通俗讲解

### 0. 整体创新点通俗解读

一块DSP像一台只会做宽整数乘法的机器。浮点乘法也可以先取出尾数，让这台机器算整数乘法，符号和指数在旁边处理。XtraMAC把不同数字格式先整理成这台机器认识的输入，并把多个小乘法放进不同位置，让一次宽乘法完成更多工作。

但是加法不能照搬这种共享：浮点加法要先对齐指数，还要规格化；整数加法只需进位。强行让宽整数通过浮点移位器会浪费资源，所以它们使用不同加法通路。

运行时换格式相当于随每批数据附带标签，标签沿流水一起走，选择相应解释和输出方式。硬件支持哪些标签在综合时确定。更多每DSP算力不保证每个模型都更快：批1解码主要等权重从存储读出，论文仿真中因此几乎没有整网提速。

### 1. 格式解码与共享整数尾数乘法

不同包装的数字先拆成尾数、符号和指数。共同机器只乘尾数，旁边根据标签处理其余信息。增加一种包装无需再造主乘法器，但要增加解码和重建逻辑。

### 2. DSP打包与类型专用累加

把几件小任务隔开放进大机器，结果会落在预定位置，再分别取出来。隔离空间不能太小，否则进位会混进旁边结果。最后相加时，整数和浮点需要不同工序，因此各用适合自己的加法设备。

### 3. 固定逻辑流水与逐周期类型切换

每份数据带一个格式标签，数据走四道工序时标签一起延迟。后面的工序读到的标签始终属于同一份数据，所以前一拍整数、后一拍浮点也能连续处理。若增加加工步骤，就必须同时延迟标签和其他输入。

### 4. 算术密度与系统瓶颈

单位面积能放更多计算机器，只在计算是瓶颈时明显有益。一次解码如果主要等待权重读出，加机器也不能加快运输。批量变大、权重能复用时，计算量增加，更多机器才发挥作用。
