# TensorExplorer: Pre-Silicon Screening of Tensor-Core Numerical 图表详解

### Fig. 1. Overview of the TensorExplorer pre-ISA screening flow. (a) Candidates are defined by numerical format, scale group, rounding policy, dot-product length, and selected operand pairing, and are characterized along quality and cost axes. (b) Cheap QSNR and static screens, promotion of regular 4/6/8-bit payloads, full workloads, and 22 nm RTL evidence progressively narrow the design space before Pareto selection. (c) The output is a measured mode record and shortlist containing a lossy range-aware 4-bit point, a cost-advantaged 6-bit middle, and near-baseline 8-bit references. Task callouts are mean accurac deltas in percentage points; the 6-bit callout is K16 area relative to b8p6sf. The shortlist is not a universal format menu, and ISA encoding and hardware integration remain downstream.

- **图示核心功能**：Figure 1 展示了 **TensorExplorer** 的端到端预 ISA（Instruction Set Architecture）筛选流程框架，该框架将数值格式的选择转化为一个可审计的、基于证据的漏斗式决策过程。

- **候选数学表达**：每个候选表示为 $x = (f, G, r, K)$，其中包含四个核心维度：
  - **Format ($f$)**：涵盖 **504 种 P3109 中间格式**（位宽 $k=3\text{--}16$）、OCP/NVIDIA/整数格式以及 **38 个供应商代理格式**（如 AMD、Huawei 等）。
  - **Scale Group ($G$)**：组大小范围 $G=4\text{--}128$，支持 **E8M0 或 E4M3 共享指数缩放**。有效存储计算公式为 $B_{\text{eff}} = b_v + b_s/G$。
  - **Rounding ($r$)**：主路径采用 **最近邻投影（Nearest Projection）**，同时以随机舍入作为消融实验对照。
  - **Length $K$ and Operand Pairs**：点积维度 $K \in \{16, 32, 64, 128\}$。支持幸存格式之间的非对称配对（例如 FP8 $\times$ FP4 混合精度路径）。

- **观测维度分层**：
  - **质量轴 (Quality)**：从低成本的 **QSNR**（量化信噪比）$\rightarrow$ 中等成本的 **PPL**（困惑度）$\rightarrow$ 高成本的 **Tasks**（下游任务精度）。
  - **成本轴 (Cost)**：从静态 **Storage**（存储开销）$\rightarrow$ 解析 **Proxies**（硬件代理模型）$\rightarrow$ 实测 **22 nm Area**（物理面积）。

该管道体现了**“候选递减，证据增强”**的筛选哲学，具体分为五个阶段：

| 阶段 | 操作内容 | 数据规模/产出 |
| :--- | :--- | :--- |
| **Cheap Screens** | 利用 QSNR 和静态微架构描述符进行快速初筛 | **24,192 行** QSNR 评估数据 |
| **Practical Promotion** | 基于**实现先验**提升符合 GPU 生态的规则宽度（4/6/8-bit），要求压缩模式节省至少 25% 有效载荷且适配 16 字节分组 | **40 个** P3109 候选点进入下一轮 |
| **Full Workloads** | 在 8 个 LLM 模型上运行完整的 WikiText-2 PPL 及零样本任务（PIQA/ARC-Easy），质量预算设为 $\Delta\text{PPL} \leq 0.1$ | **28/40** 个点通过 PPL 均值预算 |
| **Hardware Evidence** | 对幸存区域进行 **TSMC 22 nm RTL 综合**，覆盖不同点积维度 $K$ | **44 条**独特的算术数据路径 (Datapaths) |
| **Pareto Shortlist** | 在存储/PPL 和面积/任务精度空间进行帕累托最优选择 | 产生 **12+6** 个原始前沿点 |

输出的不是通用的格式菜单，而是一份**经过实测的模式记录与短列表**：

- **返回的模式记录 (Returned Mode Record)**：
  - **Operand Payload**：操作数位宽与编码定义。
  - **Scale Semantics and Packing**：缩放语义、打包策略及内存带宽影响。
  - **Arithmetic Path**：具体的算术原语、内部精度及累积策略。
  - **Reusable Modes & A×B Pairs**：可复用的多模式单元及非对称操作数对（如 MXFP8 $\times$ MXFP4）。

- **实测短列表 (Measured Shortlist)**：
  
  | 区域分类 | 代表候选 | 关键性能指标 | 架构解读 |
  | :--- | :--- | :--- | :--- |
  | **4-bit 有损前沿** | **NVFP4-like g8** | 任务精度下降 **-0.51 pp** | 测试中最强的 4-bit PTQ 点，但**未通过质量预算**；其范围语义优于纯整数或普通浮点方案。 |
  | **6-bit 成本优势中段** | **P3109 b6p5sf_g8** | 相比 b8p6sf 节省 **20.6% K16 面积** | 占据成本与质量的**最佳平衡点**；虽均值通过预算，但任务置信区间较宽（跨预算边界）。 |
  | **8-bit 质量参考基线** | **MXINT8, P3109 b8p6sf** | 任务精度变化 **+0.02~0.03 pp** | 形成无法区分的**近基线带 (Near-baseline Band)**；主要用于质量锚定和模式复用参考。 |

- **后续工作边界划分**：
  - **软件层 (Software)**：负责 **Group Size（组大小）** 的动态选择、**Operator Allocation（算子级精度分配）**（如对敏感层分配高精度）以及具体的量化配方（Clipping, Rotation 等）。
  - **后续硬件层 (Later Hardware)**：负责 **ISA 编码**、操作数交付调度、时钟树综合及物理后端闭合。

- **非单调性发现**：图示隐含了 **QSNR 与全 workload 排序的不一致性**——QSNR 能高效分离明显有损的 4-bit 区域，但在 6/8-bit 近似 ties 时失效，必须依赖昂贵的 PPL/Task 评估。
- **执行路径审计**：该框架不仅筛选静态格式，还引入了对**数值执行路径 (Numerical Execution Path $\pi$)** 的压力测试（如 KDA 场景下的 TF32 vs TF32x3 vs IEEE 差异），确保“FP32 输入”这一标签背后具有明确的算术语义契约。

- **图表核心主题**: Fig. 2 展示了 **Tensor Core** 实现块缩放点积运算的四种硬件微架构组织方式（FMA、SDA、FDA、GDFS），并将这些物理实现路径映射到六个关键的**分析成本/语义维度**。


| 组织模式 | 全称 | 核心特征 | 舍入次数 | 数据流特点 |
|---------|------|---------|---------|-----------|
| **(a) FMA** | Fused Multiply-Add | 每步融合乘法和加法 | **K次**（每步一次） | 链式结构，每级FMA接收前一级输出 |
| **(b) SDA** | Separated Dot-Add | 先算点积，后加C | **2次** | 乘法→对齐截断→加法树→首次舍入→累加C→二次舍入 |
| **(c) FDA** | Fused Dot-Add | C融合进单一归约 | **1次** | 乘法→对齐截断→(K+1):1加法树（含C）→单次舍入 |
| **(d) GDFS** | Grouped Dot-product with Fixed-point Sum | 分组精确求和 | **1次** | 组内乘法/LUT→组内精确定点求和→应用组尺度→最终归约→单次舍入 |


- **(a) FMA 链式模式**:
    - **输入**: Value codes A/B（K对，$b_v$ bits）、Scales（$b_s/G$）
    - **处理流程**: 解码（Decode）→ 提取符号/尾数/整数 → 进入 **K个串联的FMA单元** → 每个FMA执行 $a_i \cdot b_i + C_{i-1}$ 并在内部舍入 → 最终输出Y
    - **关键约束**: 这种模式**精度最高但面积和延迟最大**，因为需要维持完整的浮点链路和多次舍入控制

- **(b) SDA 分离模式**:
    - **处理流程**: 
        1. **解码**后进行 **K次独立乘法**（Mul: $p \times p$ signed）
        2. **对齐与截断**（Align + trunc.）：基于最大指数和F位宽
        3. **K:1 加法树**（Adder tree）归约乘积
        4. **首次归一化舍入**（Norm + round first rounding）
        5. **累加器加入C**（Accumulate + C）
        6. **二次舍入**（second rounding）
    - **成本特征**: 存在**双重舍入误差**，但允许乘法和加法使用不同位宽优化

- **(c) FDA 融合模式**:
    - **处理流程**: 
        1. K次乘法后**统一对齐截断**（含C值）
        2. 使用 **(K+1):1 加法树**一次性归约所有乘积和C
        3. **单次归一化舍入**
    - **优势**: 减少舍入次数，**精度优于SDA**，硬件复杂度介于SDA和FMA之间

- **(d) GDFS 分组定点求和模式**（**本文重点推荐的组织形式**）:
    - **处理流程**:
        1. **组内计算**（Mul / LUT in a group）：在组内完成乘法或查表
        2. **组内精确定点求和**（Group sum K/G, exact FXP）：**这是关键创新点**——在应用组尺度之前，先以**定点精确方式**完成组内求和，避免中间结果的浮点舍入
        3. **应用组尺度**（× group scale scale mantissa）：将组尺度指数应用于组总和
        4. **对齐截断**（Align + trunc. sums + C）
        5. **(K/G+1):1 加法树**归约各组结果
        6. **单次归一化舍入**
    - **语义优势**: **完美匹配OCP/P3109等块缩放格式的语义**——先在组内保持精确，再统一缩放，最小化量化误差传播


图中右侧括号将硬件组件映射到**解析成本模型**的六个维度：

| 维度符号 | 名称 | 硬件对应 | 成本影响因子 |
|---------|------|---------|-------------|
| **$B_{\text{eff}}$** | 有效存储 | Value codes + Scales | $b_v + b_s/G$（值位宽 + 缩放因子分摊） |
| **$D_{\text{dec}}$** | 解码负载 | Decode 单元 | 有限码点数 × 解码后的符号/指数/尾数载荷宽度 |
| **Scale path** | 缩放路径 | Group scale 处理 | 共享指数处理的逻辑开销 |
| **$M_{\text{mul}}$** | 乘法代理 | Mul / Mul-LUT | $\propto p^2$（与解码后精度p的平方成正比） |
| **$R_{\text{red}}$** | 归约树 | Adder tree + Accumulator | 取决于归约深度和累加器位宽 |
| **Reuse** | 模式复用 | Mode select + 共享算术核 | 底部显示：**切换解码器，算术核心按最宽模式 sizing** |


- **模式复用策略**（底部 "Mode select" 框）:
    - 当支持多种数值格式（如同时支持P3109的4/6/8-bit）时，**不需要为每种格式复制完整 datapath**
    - 而是**共享最宽的算术核心**（如按8-bit sizing乘法器和加法树），仅通过**模式选择信号切换前端解码器**
    - 论文实测表明：8模式K128单元相比其最宽构成单元仅增加 **15.1% 面积**

- **GDFS 的特殊地位**:
    - 图中(d)列是**唯一**在应用组尺度前执行"**exact FXP**"（精确定点求和）的组织方式
    - 这直接对应论文中提到的**硬件/软件边界划分**：硬件负责精确的组内求和，软件负责裁剪、旋转等策略决策
    - 解决了**零点 hazard**：当某组乘积恰好为零但携带大尺度指数时，GDFS 可以先检测零再决定指数，避免 scale-first 树导致的过移位问题（公式10的硬件语义）

- **成本-精度权衡的可视化**:
    - **FMA**: 高精度、高成本（适用于TF32x3等精度敏感路径）
    - **SDA**: 低精度、低成本（可能用于NVFP4等有损前沿格式）
    - **FDA/GDFS**: **平衡点**——GDFS特别适合块缩放格式，在保持精度的同时通过分组减少归约树深度（从K:1降至K/G:1）


- 该图解释了为何 **b6p5sf_g8** 能成为**面积效率最优**的实用候选：
    - 采用 **GDFS 或 FDA 组织**，6-bit 值宽度使得乘法器面积（$M_{\text{mul}} \propto p^2$）显著小于8-bit
    - 组大小 G=8 使得归约树深度减半，进一步节省 $R_{\text{red}}$ 开销
    - 实测 **K16 面积 4188 μm²**，比 b8p6sf 参考节省 **20.6%**

- 解释了**非单调性现象**：编码位宽（encoded width）不能预测实际面积，因为：
    - E2M3（6-bit）和 E4M3（8-bit）可能共享相同的有效尾数精度（p=4），导致**解码和对齐逻辑成本相近**（如图6(b)所示 MXFP8×MXFP6 E2M3 反而比 MXFP8×MXFP8 大0.91%）

- **图像定位与核心主题**
    - 该图为 **Figure 3 的 (a) 子图**，标题为 **"Inherited-scale control"（继承缩放控制）**。
    - 其核心目的是验证**组大小（Group Size, G）非单调性**的一个关键基准对照实验：即当较小的分组（g8）**被动继承**较大分组（g16）的缩放因子（Scale）时，量化结果是否发生改变。

- **视觉结构与逻辑流程**
    - **顶层节点**：**g16 parent**（g16 父级），代表原始的、以 16 个值为一个共享缩放组的量化配置。
    - **转换机制**：箭头旁标注 **"inherit parent scale + projection"**（继承父级缩放 + 投影）。这意味着 g8 的子组并非独立计算其最优缩放因子，而是直接复用其所属 g16 父组的缩放系数，并在此约束下进行最近邻投影（Nearest Projection）。
    - **底层节点**：两个 **forced g8 child**（强制 g8 子级），代表在继承约束下被人为拆分或定义的 g8 分组。
    - **底部统计结论**：
        - **max |Q8 forced - Q16| = 0**：这是最关键的定量结果。它表明在所有测试样本中，强制继承缩放的 g8 量化值（Q8 forced）与原始 g16 量化值（Q16）之间的**最大绝对误差严格为零**。
        - **7 formats × 8 models; 1,344 tensors**：明确了实验的覆盖范围。该结论跨越了 **7 种数值格式**、**8 个大语言模型（LLM）**，共计对 **1,344 个线性层权重张量（tensors）** 进行了逐元素验证。

- **深层含义与论文论证价值**
    - **确立“无损”基线**：此图证明了**分组大小的物理拆分本身不引入信息损失**，前提是缩放语义保持不变。这为后续对比“独立缩放（Independent Scaling）”的 g8 实验提供了完美的**零偏差对照组**。
    - **解耦变量**：它成功将“改变组大小”这一操作与“重新计算缩放因子”这一操作解耦。论文后续指出，一旦允许 g8 进行**独立缩放**，会有 **23.2%–45.9% 的缩放码（scale codes）发生改变**，从而导致模型质量（PPL）出现波动。
    - **支撑 RQ3（研究问题 3）**：该图直接回应了“为何组大小和 QSNR 不是简单的排序器”这一问题。它说明**更小的组并不自动意味着更高的精度**，精度的变化源于缩放策略的改变而非单纯的分组粒度细化。

- 深度分析与异常点解读：
    *   **NVFP4 的极端敏感性**：在所有测试格式中，**nvfp4** 表现出极高的不匹配率 (**45.9%**)，几乎是其他格式的两倍。这表明 NVFP4 格式在处理**分组粒度 (Group Size) 变化**时，其**缩放语义 (Scale Semantics)** 极不稳定。较小的分组会导致其需要频繁地重新调整指数范围以适应局部数据分布。
    *   **P3109 与 OCP/INT 格式的稳定性**：包括 **MXFP4, MXINT4, MXINT8** 以及 **P3109 系列 (b6p5sf, b8p6sf, b8p7sf)** 在内的其余格式，不匹配率均稳定在 **23.2% - 23.8%** 这一狭窄区间内。这说明对于大多数主流低比特格式，缩小分组规模大约会导致约 **四分之一** 的缩放码发生重构。

- 论文结论映射与架构启示：
    *   **推翻“分组越大越好”的直觉**：该图表有力地支持了论文关于 **RQ3 (Research Question 3)** 的结论——**Group Size 并非简单的单调排序器 (Monotone Ranker)**。
    *   **量化器行为的本质改变**：独立的小分组不仅仅是存储层面的切分，它实际上**改变了底层量化器的行为 (Changes the Quantizer)**。由于 Scale Code 的大面积变动，随之而来的**裁剪模式 (Clipping Pattern)** 也会发生改变，进而影响最终的模型精度（如 Figure 3c 所示的 PPL 变动）。
    *   **硬件设计考量**：对于硬件架构师而言，这意味着支持可变分组大小 (Variable Group Size) 不能仅视为软件层面的打包策略调整，它涉及到**缩放指数解码逻辑 (Scale Exponent Decoding Logic)** 和**动态范围适配**的实质性变化，尤其是针对 NVFP4 这类对分组敏感的格式。

*   **图表核心主题**：该图揭示了**“Same FP32, different path”**（相同的FP32数据类型，不同的执行路径）这一关键概念。它论证了**仅凭外部数据类型（如FP32）无法完整定义硬件执行的数值契约**，内部算术路径的选择同样至关重要。

*   **上层逻辑：计算范式的转变**
    *   **左侧节点（Direct recurrence）**：代表传统的**直接递归**模式。其特征为**本地状态更新（local state update）**且**无仿射前缀（no affine prefix）**。在这种模式下，状态更新通常是局部的、顺序的。
    *   **右侧节点（Context-parallel segment）**：代表**上下文并行段**。这是现代大模型推理（如KDA/KCP）中采用的高级优化技术。其数学表达为前缀合并公式 **$S' = MS + H$**，其中涉及矩阵 $M$ 和向量 $H$ 的仿射变换。
    *   **箭头含义**：表示从简单的递归逻辑向复杂的上下文并行逻辑的演进。这种结构性的变化引入了新的数值误差传播风险。

*   **下层流程：隐藏的精度差异链**
    该部分拆解了在“FP32操作数”这一表象下，实际执行过程中可能存在的精度分叉点：
    *   **FP32 operands**：输入数据在软件层面被声明为FP32精度。
    *   **Triton tl.dot**：调用Triton编译器的点积原语。这是关键的**抽象边界**。
    *   **dot precision**：**核心变量**。在实际硬件（如NVIDIA Tensor Core）上执行时，`tl.dot` 默认可能使用 **TF32**（19位有效精度）而非完整的IEEE FP32（32位）。此外，还存在高精度选项如 **TF32x3**（三重TF32分解）或强制 **IEEE** 模式。
    *   **state propagation**：最终的状态传播结果。由于中间 `dot precision` 的不同，即便输入相同，最终的累积误差也会显著不同。

*   **与论文论点的关联（RQ4: 执行路径压力测试）**
    *   此图是论文 **Section VI-D** 中 **KDA (Kimi Linear Attention) 案例研究** 的概念基础。
    *   论文通过实验证明：在深度为64的合成KDA链式测试中，使用 **TF32** 路径的中位相对状态误差高达 **$3.76 \times 10^{-2}$**；而切换到 **TF32x3** 或 **IEEE** 路径后，误差分别骤降至 **$2.66 \times 10^{-5}$** 和 **$1.63 \times 10^{-6}$**。
    *   **设计启示**：架构设计不能仅关注数据位宽（如4-bit vs 8-bit），还必须审计**算子内部的执行路径**。对于深度状态传播（Deep Stateful Propagation）场景，必须显式暴露高精度路径（如TF32x3/IEEE），而不能依赖隐式的默认低精度路径（如TF32）。

*   **总结**
    此图直观地展示了 **TensorExplorer** 框架超越传统格式筛选的独特视角：**数值精度不仅取决于“存什么”（格式），还取决于“怎么算”（执行路径）**。这对于设计下一代支持混合精度和复杂并行模式的张量核心（Tensor Core）具有重要的指导意义。

    - **QSNR 的筛选效能 (Screening Efficacy)**：

    - 该图支撑了论文提出的**漏斗式筛选策略 (Evidence Funnel)**：
