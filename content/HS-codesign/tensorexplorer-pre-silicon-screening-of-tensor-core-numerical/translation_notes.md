# TensorExplorer: Pre-Silicon Screening of Tensor-Core Numerical 原文翻译

# TensorExplorer：Tensor Core 数值格式的流片前筛选

Wei Liu, Yi Yu, Qianliang Liu, Xiaoyou Song, Xuanbo Gao, Yuhan Wang, Yumin Hou, Hu He

摘要—Tensor core 必须从在数值表、缩放方式、分组和算术成本上各不相同的格式中选择一份执行模式菜单。TensorExplorer 让这一 ISA 之前的选择变得可审计。它以码点检查和 QSNR 对 504 个 P3109 中间格式以及面向 OCP 和厂商的候选格式进行筛选，随后使用完整的 WikiText-2 PPL、零样本任务、打包和单元面积对幸存者进行分类。在最近邻舍入的仅权重 PTQ 下，类 NVFP4 的 g8 是所测试中最强的有损 4-bit 点。面向 P3109 的 6-bit b6p5sf\_g8 在使用比 b8p6sf 参考少 20<sub>.</sub>6% 的 K16 面积的同时，损失 0<sub>.</sub>056 个任务百分点；其任务区间跨越了预算线。八位候选格式构成一个未决的近基线带。独立的小组缩放会改变 23<sub>.</sub>2–45<sub>.</sub>9% 的缩放码。八种 P3109 模式在最宽组成单元之上增加 15<sub>.</sub>1% 的面积，而操作数宽度并不能一致地决定混合对的面积。一项受控的 KDA 形状 affine 链路压力测试增加了执行路径边界：在深度 64 处，显式 TF32、TF32x3 和 IEEE 点积相对于 FP64 的中位相对状态误差分别为 3<sub>.</sub>76 × 10<sup>−2</sup>、2<sub>.</sub>66 × 10<sup>−5</sup> 和 1<sub>.</sub>63 × 10<sup>−6</sup>，对应的独立 kernel 成本为 1<sub>.</sub>00×、1<sub>.</sub>88× 和 20<sub>.</sub>54×。TensorExplorer 在 ISA 集成之前返回一份经过测量的精度区域候选清单，并附带质量、实现和路径组合边界。

索引词—tensor core、执行模式、数值格式、microscaling、IEEE P3109、QSNR、困惑度、硬件成本证据。

## I. 引言

低精度不再仅仅是一个位宽选择。OCP microscaling、NVIDIA 风格的 FP4、整数模式、AMD 与华为的格式，以及 IEEE P3109 如今提供了各不相同的数值表和缩放规则 [1]–[10]。Tensor core 无法将这一家族整体暴露出来。每一种额外的模式都会消耗打包、算术、验证、编译器和 ISA 预算。

第一个反例出现在 4-bit 候选格式中。在相同的每权重 5.0 有效比特下，最便宜的算术单元并不是最佳的工作负载点。类 NVFP4 的 g8 在 PIQA/ARC-Easy 上损失 0<sub>.</sub>505 个百分点；在相同的仅权重 PTQ 协议下，MXINT4 和 MXFP4 分别损失 1<sub>.</sub>361 和 1<sub>.</sub>804 个百分点。范围和缩放语义的重要性超过了解码器面积的适度增加。面向 P3109 的候选格式揭示了第二个权衡。六比特保留了大部分八比特的质量，同时降低了载荷和算术面积，但面向字节的操作数暂存可能抹除其密度优势。

两个操作数也不必共享同一种格式。DeepSeek-V4 报告了 FP4 路由专家权重与 FP4×FP8 计算路径的组合。当前硬件赋予这一对与 FP8×FP8 相同的峰值 FLOPs；一条专用路径理论上可以将效率提高三分之一 [11]。NVIDIA 的块缩放 MMA 接口已经允许独立的 FP8、FP6 或 FP4 操作数类型 [12]。因此，对称的 $M \times N$ 排序遗漏了一个由部署驱动的空间。TensorExplorer 通过仅组合在单格式筛选中幸存的区域来控制其扩展。

现有工具在这一决策的两侧止步。格式规范定义了编码。硬件感知量化选择的是模型如何使用已经存在的模式 [13]–[18]。可配置算术实现的是在成员已被选定之后的菜单 [19]–[22]。缺失的步骤是 ISA 之前的选择：哪些数值约定能够在工作负载中幸存、证明其存储行为的合理性，并偿还它们所需的算术路径？

TensorExplorer 以一个证据漏斗填补了这一步骤。它记录每个候选格式的数值表、组缩放、舍入规则、存储成本和算术路径。QSNR 对廉价探测进行排序。完整的 PPL 和完整任务赋予质量标签，随后打包和 22 nm 综合区分数值上相近的幸存者。宽度准入在工作负载排序之前固定：压缩模式必须至少节省 25% 的原始数值载荷，被准入的载荷必须能装入一个 16 值数据包，而 8 比特仍然是字节通道参考。面向公开 GPU 的 4/6/8 比特宽度构成实际菜单。一个单独的不规则宽度保留集用于测量这一生态先验所排除的内容。

三个实用区域浮现出来。类 NVFP4 的 g8 是所测试的最强 4-bit PTQ 点，但它仍然处于两个质量预算之外。P3109 b6p5sf\_g8 占据了成本优势的中间地带；其均值通过，但其任务区间跨越了预算线。八比特 P3109 和 MXINT8 构成一个未决的近基线带。组大小贡献了另一个反例：在继承父缩放的情况下 g8 精确复现 g16，而独立缩放会改变 23<sub>.</sub>2–45<sub>.</sub>9% 的采样缩放码，并且可以逆转近乎持平的 PPL 排序。

现代 kernel 增加了一种互补的失效模式：分解可以在不改变可见数据类型的情况下改变算术路径。FLA 的 KDA 上下文并行路径通过 Triton tl.dot 合并名义上的 FP32 affine 变换，而其 NVIDIA FP32 tensor core 默认为 TF32 [23]–[25]。局部误差可以在后续变换中重新进入。因此 FLA PR #1180 为状态更新和 affine 合并添加了可选的 TF32x3，保持默认不变，并在非 TF32 平台上使用 IEEE [26], [27]。这促使我们审查数值执行路径，而不是把“FP32 输入”当作完整的约定。

本文做出三项贡献：

1) 我们通过显式的准入、晋级、质量通过、有损前沿和控制规则，使 ISA 前的格式选择可复现。由此产生的记录将硬件可见的数值约定与模型特定的量化策略分离，并审计所选算术模式如何沿数值执行路径进行组合。

2) 我们在 504 个 P3109 中间格式以及面向 OCP、NVIDIA、AMD、华为和整数的候选格式中识别出不同的实用 4/6/8 比特区域。完整工作负载揭示了组大小的非单调性，并表明 QSNR 与宽度优先级会随筛选目标的变化而交换优势。

3) 我们通过打包、一个解析成本模型以及实测的 22 nm 单元 PPA 来量化实现后果。四十四条 P3109 按格式划分的 $\beta$ 数据路径、二十四个可复用单元，以及九个对称/非对称 MXFP4/6/8 单元，展示了编码宽度在何处能够预测成本，以及在何处失效。

## II. 问题：选择硬件可见的精度候选

设计问题在于将模式比特花费在哪里。即使两个候选存储相同数量的比特，精度模式仍会消耗解码器、缩放、乘积、归约和验证预算。TensorGauge 提供了问题的另一半：累加顺序、中间精度和截断点可以在数学 GEMM 不变的情况下改变模型行为。TensorExplorer 通过一个关于 QSNR、PPL、任务精度、有效存储和有界单元面积证据的前沿将这些压力结合在一起。

一个候选通过 tensor core 模式可以暴露的字段进入 TensorExplorer：数值编码、共享缩放分组、舍入行为和算术路径。格式、精度/范围、组大小、舍入和 $\beta$ 是旋钮。QSNR、PPL、任务精度、存储和单元面积是观测值。晋级要求工作负载证据与成本证据之间的一致。

一个点前进，要么因为它通过了当前闸门，要么因为一条预先声明的覆盖规则将其保留为有损前沿或控制点。QSNR 提出优先级，工作负载赋予输出标签，一个单独的保留集审计被排除的形状层。硬件成本区分实际的幸存者。输出是一组用于后续 tensor core 设计的紧凑数值格式区域。

## A. 候选格式到模式的解释

筛选输出是一种架构模式选择。执行模式（execution mode）定义了一族 GEMM 指令的硬件契约：操作数码本解码、共享 scale 的解释方式、打包粒度、乘积/归约宽度、累加器策略、舍入语义、执行路径绑定以及合法的模式位。我们用 <sub>�</sub> 表示数值执行路径：即用于实现某个数学等价算子的算术原语、内部精度、归约与组合的具体序列。多个 PTQ 点可能共享同一数据通路模式，仅在软件分组或打包方式上不同。P3109 使这一区分变得有用，因为它定义了一个大型参数化家族，硬件必须从中选出一个小的子集。TensorExplorer 识别出那些值得为其分配模式位与解码器支持的成员，并围绕一个共享的 MMA 数据通路构建。

该映射止步于 ISA 提案之前，但它携带的结构信息比基准测试标签更多。每一个入围候选都定义了其操作数负载、scale 元数据、算术路径、舍入行为以及软件接口。Group size 恰好说明了这种分离：它属于操作数元数据与存储契约；在单单元 PPA 代理中，它并不会产生另一个算术数据通路。

主候选仍为 $x = ( f , G , r , K ) ; \pi$；并不是在所有 504 种格式上再增加一个笛卡尔维度。TensorExplorer 而是对选定复合算子审计 <sub>�</sub>，这些算子的分解可以反复暴露所选的算术语义。因此，格式选择是首要的选择器，而执行路径压力测试则验证该模式嵌入到现代 kernel 图中的实际表现。

对称候选是更大操作数对空间的对角线。一旦某个格式通过了单体筛选，TensorExplorer 可将其作为 A 或 B 与另一幸存者组合。有序对保留独立的解码与 scale 路径，而乘法与归约则按联合方式确定规模。这种分阶段扩展与现有的混合 FP8/FP6/FP4 MMA 接口相吻合，同时不将每一个合法配对都视为有用的硬件模式 [12]。

返回的记录包含操作数负载、scale 语义、打包方式、算术路径描述符以及可复用的模式集合。后续的 tensor core 工作再决定 ISA 编码、swizzle、操作数采集器、调度以及布局后集成。这一边界将精度筛选与硬件实现分离开来。

## C. 筛选目标与 Pareto 选择器

初始选择器结合两个过滤器。QSNR 与静态描述符用于识别较弱或被支配的数值区域；一个实现先验（implementation prior）则保留那些能够合理映射到目标 tensor-core 路径的位宽与分组。随后，完整的 PPL 与任务评测会替代数值代理，对被提升的点进行评估。当某个候选点在所采用的质量与成本坐标上均不劣于另一候选点，且至少在一个坐标上严格更优时，该候选点支配后者。

实现先验是显式的。公开的 P3109 中间版表格涵盖 $k ~ = ~ 3 – 1 6$ 个存储值位宽，但 pre-ISA 筛选在看到工作负载优胜者之前需要一个准入规则。当 16 个值的载荷能装入一个 16 字节的暂存包，且压缩位宽相对于 8 位至少节省 25% 的原始值流量时，TensorExplorer 准入面向公开 GPU 的 4/6/8 位位宽。4 位携带 8 字节的值，6 位携带 12 字节，8 位携带 16 字节。不规则位宽的对照组用于度量这一生态系统先验的代价；它们并不被提议作为额外的硬件模式。

单侧平均质量预算为 ΔPPL ≤ 0<sub>.</sub>1 与 ΔAcc ≥ −0<sub>.</sub>15 个百分点。前者相当于平均未量化 PPL 的 0<sub>.</sub>93%；后者相当于平均任务基线的 0<sub>.</sub>19%。这些是工程容差，而非显著性阈值。选择器输出三个可复现的标签。质量通过（quality-pass）点满足所有可用的平均预算；有损位宽前沿（lossy width-frontier）点未通过质量预算，但作为某个被准入位宽的非支配代表被保留；对照组（control）仅用于暴露某个失败或被排除的层。“被提升”（Promoted）意味着被调度进入下一证据阶段，而非获得实现背书。另外，一个质量通过点仅当其 95% 模型簇区间同样保持在对应的单侧预算之内时，才被视为区间确认（interval-confirmed）。平均状态与区间状态永远不会被合并。

我们使用“NVFP4-like”来指代我们筛选流程中的 E4M3 缩放 FP4 候选格式，而非 NVIDIA Blackwell NVFP4 生产实现的逐位精确模型——后者的公开描述包括 16 值微块以及一个额外的更高层级缩放约定 [3]。这一命名边界很重要，因为 TensorExplorer 研究的是执行模式区域与单元级成本，而非专有 tensor-core 行为。

## III. 筛选方法

评估流程刻意采用非对称设计。廉价的筛选负责提出区域；完整工作负载负责赋予质量通过、有损前沿或对照标签。TensorExplorer 枚举数值格式、分组大小与舍入候选，用 QSNR 与静态微架构描述符进行收窄，运行完整的 LLM PPL 加完整任务，并将 RTL 级的逐单元 PPA 附加到由显式规则保留的实际 4/6/8 位区域上。一个单独的奇数位宽保留集（holdout）审计这一实现先验，但不会重新定义面向 GPU 的候选菜单。相对于 TensorGauge，本文的贡献正是这一可审计的“筛选—分类—成本”闭环。

TensorGauge 提供了位精确（bit-accurate）的数值模型，可显式控制累加结构、舍入路径与中间保留策略。该模型被接入 PyTorch，使硬件启发的算术语义能够传播到完整的神经网络训练与推理中。本扩展加入了一个轻量级硬件成本桥接：用于分组大小权衡的有效存储位数、用于筛选的解析式乘法器/解码代理，以及针对一小批精选的 OCP 类与 P3109 点积单元的实测 22 nm PPA。

该工作流在三个证据层上评估每个精度候选。首先获得数值签名；随后得到工作负载结果；最后为被提升的区域附加有界的逐单元硬件成本。连接后的表格构成 Pareto 选择接口：每一行都携带足够的质量与成本字段，用于检验支配关系，并解释某个点为何被提升、被降级或作为平局保留。所得前沿是在已评估候选之上观察得到的，并限定于所声明的量化策略、激活配方与 P3109 编码假设。

QSNR 是筛选流程的快速通道。在 P3109 路径中，候选/模型/分组的网格覆盖 504 个已实现的 P3109 格式，横跨八个模型与六种分组大小，产生 24,192 行。每一行使用相同的确定性逐层采样策略，每个线性层至多 16 个分组，种子为 3109。该网格在候选上穷举，而张量采样使这一遍历足够廉价，可在 PPL 之前运行。

实现先验定义了 40 个有符号有限的 4/6/8 位格式/分组候选、12 个任务关键点，以及六个强任务入围者。一项回溯性预算扫描在该固定宇宙内重放两种确定性排序。平均 QSNR 优先按 QSNR 递减排序，其次按候选 ID 排序。位宽优先按值位数递减、有效位数递减排序，然后按候选 ID 排序。评估全部 40 个候选套件（即 320 次模型级 PPL 运行）可找到 28 个位于 0.1-PPL 预算之内的点以及四个被接受的前沿点。

有用的排序取决于预算需要恢复什么。在 24 个套件时，两种策略均找到 24 个被接受的点，但位宽优先覆盖四个被接受前沿点中的三个，而 QSNR 覆盖两个。在 28 个套件时，QSNR 找到全部 28 个被接受的点及全部四个前沿点；位宽优先找到 27 个与三个。位宽优先在 29 个套件时达到两项总数。因此，40 到 28 的缩减度量的是避免穷举重放的价值，而 QSNR 相对于所指定的位宽先验的增量优势是一个候选套件、八次模型级 PPL 运行，即可完成被接受区域的覆盖。该截断是回溯性的，并不能确立对全部 504 种格式的召回率。

一个确定性的 16 点保留集另行覆盖被排除的位宽、五个 QSNR 分位数以及高成本对照。Mistral-7B 与 Qwen3-8B 在同一匹配的分词器/工具链下，针对保留集与被提升的参考点运行完整的 WikiText-2。该审计检验的是生态系统先验排除了什么；它并不扩大所提议的硬件菜单。

仅 PTQ 遗留了一个悬而未决的问题：一旦量化参与到参数更新中，候选清单是否会立即失效？我们加入三个小型训练检查。其中两个是字节级 WikiText-2 试点，一个是因果 Transformer，一个是 BERT 风格的 masked-LM Transformer，各约 0.48M 参数、512 个优化器步、STE 伪量化 Linear 权重，并使用完整验证流评分。第三个复用 TensorGauge 的 PureTorch BERT 类 SST-2 配方：5.97M 参数、3 个 epoch、完整的 67,349 例训练集与完整的 872 例验证集。这些运行是针对本闭环的无崩溃（no-collapse）证据。它们将生产级 FP4 训练配方、激活量化、优化器状态压缩、损失缩放、长程收敛与多种子统计留给训练领域的文献。

各阶段具有不同的证据角色。QSNR 提出区域并排定优先级；保留集度量筛选召回率；完整 PPL 与完整任务赋予区域标签；硬件证据仅在一个数值候选仍然有意义之后才被引入。一个较低的面积极数无法挽救明确的工作负载失败。

## IV. 数值与硬件证据

## A. 工作负载可见的数值语义

所保留的 TensorGauge 证据为从算术表征到精度筛选提供了桥梁。GEMM 在浮点算术下不满足结合律；分块、归约树、融合点积、分离的点加单元以及内部截断点，都可能使同一数学运算产生不同的工作负载结果。因此，仅靠局部单元容差是不够的。

对 TensorExplorer 而言最相关的细节，是指数或共享尺度对齐之后产生的中间尾数。保留每一个尾位代价高昂，因为移位器、加法器、保护路径和累加器都会随对齐宽度而增大。我们转而将保留的尾数位数视为一种算子资源。一个基本点积需要能在保留工作负载的前提下维持工作的最小内部精度；一个复合算子则需要与理想融合参考进行对比。第 VI-A2 节用低/高精度菜单而非为每个 Transformer 算子配置独立物理数据通路来测试这一想法。

1) 有状态执行路径放大：一个上下文并行的 KDA 片段可以由一个仿射状态变换概括

$$
S _ { i } = M _ { i } S _ { i - 1 } + H _ { i } ,\tag{5}
$$

且相邻变换按 $M _ { 0 2 } ~ = ~ M _ { 1 2 } M _ { 0 1 }$ 与 $H _ { 0 2 } = M _ { 1 2 } H _ { 0 1 } + H _ { 1 2 }$ 复合 [23], [24]。若实际实现的路径转而求值

$$
\widehat { S } _ { i } = \big ( M _ { i } + \Delta M _ { i } \big ) \widehat { S } _ { i - 1 } + H _ { i } + \delta _ { i } ,\tag{6}
$$

则其一阶意义下的状态误差满足

$$
e _ { i } \approx M _ { i } e _ { i - 1 } + \Delta M _ { i } S _ { i - 1 } + \delta _ { i } ,\tag{7}
$$

并可示意性地写为

$$
e _ { n } \approx \sum _ { i } \left( \prod _ { j = i + 1 } ^ { n } M _ { j } \right) \epsilon _ { i } .\tag{8}
$$

第一个量是单个 m×n 运算中的局部算术误差；第二个量是一连串变换复合之后的执行误差。这并不意味着线性或指数增长：传播行为取决于转移矩阵、条件数、状态幅值以及复合深度。TensorGauge 揭示了局部与 GEMM 层面的语义；这一压力测试用例则审计的是 kernel 图如何将二者复合起来。

## B. 候选级硬件成本证据

硬件测量从两个方面改变了候选清单。低面积单元无法挽救一个在完整工作负载上失败的格式。反之，当所选解码器共享最宽的算术路径而非复制完整单元时，P3109 模式多样性就变得廉价。

证据随筛选成本递增而累积。有效位数刻画了尺度摊销。解码与乘法器代理在综合之前就暴露了范围/精度压力。随后，选定的 22 nm 单元对这些代理进行校准，而可复用的 P3109 单元则度量了保留多种模式的成本。在该模型中，分组大小改变的是存储与打包方式；它并不会为每个软件配置点都创建一个不同的算术模块。

面积是 Pareto 选择器所使用的硬件变量。无向量（vectorless）Design Compiler 功耗与真实操作数活动率则作为方向性异常的诊断指标。所得数值是综合前（pre-layout）计算单元的锚点；芯片级的操作数传送、调度与物理收敛属于后续的集成阶段。

1) 格式到微架构的成本模型：该成本模型解释了为何相同的外部位宽会带来不同的面积结果。一条 4 位整数通路、一张 4 位浮点数值表与一条 4 位 NVFP4 类缩放通路存储的位数都不多，但它们对解码、缩放、乘积与归约资源的压力各不相同。对一个块缩放点积，单元级成本可分解为

$$
\begin{array} { r l } & { C _ { \mathrm { u n i t } } ( f , K ) = C _ { \mathrm { d e c } } ( f ) + C _ { \mathrm { s c a l e } } ( f ) + K C _ { \mathrm { m u l } } ( f ) } \\ & { \qquad + C _ { \mathrm { r e d } } ( K , w _ { f } ) + C _ { \mathrm { a c c } } ( w _ { f } ) + C _ { \mathrm { m o d e } } , } \end{array}\tag{9}
$$

其中 $C _ { \mathrm { d e c } }$ 覆盖数值表或整数解码，$C _ { \mathrm { s c a l e } }$ 覆盖共享尺度指数处理，$C _ { \mathrm { m u l } }$ 是每条通道的乘积路径，$C _ { \mathrm { r e d } }$ 是加法器/归约树，$C _ { \mathrm { a c c } }$ 是累加器配置，而 $C _ { \mathrm { m o d e } }$ 是可复用多格式支持带来的控制/解码器开销。在该代理模型中，权重分组大小 $G$ 影响的是 $B _ { \mathrm { e f f } }$ 与打包而非算术单元，因此 TensorExplorer 在计算 Pareto 前沿之前将存储成本与数据通路成本两个维度分开处理。

2) 块缩放 FP4 模式的微架构边界：块缩放模式将局部算术语义与模型策略区分开来。硬件负责数值与尺度的解码、对齐、零值处理、保留尾位、累加以及可复现的舍入原语。软件则选择裁剪、旋转、层豁免与训练估计器。Quartet II、UFP4 以及 INT 与 FP 之争说明了这条边界为何重要：它们的 RTN、MS-EDEN、旋转与网格选择可以不断演进，而无需改变指令的局部算术契约 [28]–[30]。

一个局部角落案例使这一划分变得具体。如果某个分组的乘积和恰为零但携带较大的尺度指数，尺度优先的指数树会抬高 maxE 并使非零分组发生过度移位。软件无法在不重放隐藏点积分组的情况下修复此问题。令 $\begin{array} { r } { p _ { g } \ = \ \sum _ { i \in g } q _ { i } ^ { A } q _ { i } ^ { B } } \end{array}$，并令 $E _ { g } ^ { \mathrm { s c a l e } }$ 为两个分组尺度带来的指数贡献。指数比较应当先对精确零值进行门控：

$$
e _ { g } = \left\{ { \begin{array} { l l } { - \infty , } & { p _ { g } = 0 , } \\ { E _ { g } ^ { \mathrm { s c a l e } } + \lfloor \log _ { 2 } \vert p _ { g } \vert \rfloor , } & { p _ { g } \neq 0 . } \end{array} } \right.\tag{10}
$$

该实验工件（artifact）的重放同时展示了这一隐患及其可见性边界。一个 Qwen2.5-0.5B 的 NVFP4 层记录到 0<sub>.</sub>634% 的内部 maxE 不匹配率和 0<sub>.</sub>391% 的零点积分组率，然而尺度优先与零值过滤后的输出在 35 位与 16 位小数位时完全一致。差异在 14 位时出现；到 13 位和 10 位时，尾宽损失占主导。因此，精确零值门控是一项硬件语义，而保留精度存在工作负载上的最优点，配置配方选择则仍属软件策略。

3) 块缩放的精度/范围成本与综合：块缩放的结果说明了为何仅凭数值位数是一个不完整的成本信号。一个候选格式要为其数值编码、共享尺度、该尺度的打包方式以及消费二者的算术路径付费。因此，我们采用一个保守的静态单单元代理作为筛选层。参数化的 Chisel 单元覆盖类 OCP 格式、最终的 P3109 候选清单以及选定的 MXFP8/MXFP6/MXFP4 混合操作数对。在该配对研究中，MXFP6/8 指的是一条带 E8M0 分组尺度、具有 E3M2、E2M3 或 E4M3 形态数值通路的有限格式；它是一个格式形态代理，而非一致性声明。对于位宽为 $b _ { \nu }$ 的数值字段、$b _ { s }$ 位的共享尺度以及分组大小 $G$，每个权重的存储成本为

$$
B _ { \mathrm { e f f } } = b _ { \nu } + \frac { b _ { s } } { G } .\tag{11}
$$

这将数值精度与尺度摊销分离开来。我们还记录了两个轻量级硬件代理：乘法器代理 $p ^ { 2 }$（其中 $p$ 是解码后的有效数字或整数精度），以及解码表载荷代理，其值等于有限码点数量乘以解码后的符号/指数/有效数字载荷位宽。图 2 将这一分解映射到 FMA、分离点加、融合点加以及分组算术组织形式上；选定的类 OCP 与 P3109 单元则通过综合与 k 缩放分析闭环验证。

## VI. 结果：五个筛选问题

五个问题将候选格式族收窄为一条经过测量的边界。类 NVFP4 的范围语义定义了已观测到的最佳 4 位 PTQ 区域。P3109 b6p5sf 占据了一个面积高效的 6 位中间地带；MXINT8 和 8 位 P3109 提供了近基线的参考。训练、组大小、算子、打包和硬件证据随后决定了应如何解读这些实用区域。

## A. RQ1：工作负载筛选后保留哪些精度区域？

实用的软件/硬件数据集包含 58 个点。每个点记录有效存储、PPL 变化量、PIQA/ARC-Easy 准确率变化量以及可用的单元级 PPA。其中 12 个点位于原始存储/PPL 前沿上；30 个任务成本点中有 6 个位于原始面积/准确率前沿上。在 40 点的 P3109 子集内，没有任何一种回顾式排序能在所有预算下占优。Width 优先在预算为 24 时找到更多被接受的前沿点；QSNR 在预算为 28 时找到全部 28 个均值预算点，比 width 优先早一个套件。最终得到的菜单包含质量通过的参考点、一个有损的 4-bit width 前沿，以及明确的控制点。该筛选流程优先安排昂贵的评估，而不是将每一个被评估的点都转化为推荐。

质量排序还取决于格式家族。在 OCP/NV/INT 就近舍入（nearest-rounding）扫描中，MXINT8 保持在近基线区间（最佳平均 PPL 变化量为 −0<sub>.</sub>004824，最佳平均准确率变化量为 0<sub>.</sub>031886 pp）。NVFP4 类候选是该协议下唯一具有竞争力的 4-bit 浮点风格 PTQ 点：nvfp4\_g8 的 PPL 变化量为 0<sub>.</sub>511259，准确率变化量为 −0<sub>.</sub>505120 pp。MXINT4 损失超过 1 个 pp，而 MXFP4 是该协议下最弱的 4-bit OCP 类候选。这是对该漏斗流程的一次有效合理性检验。在具有相同 5.0 有效比特每权重的候选中，TensorExplorer 并非简单地偏好最廉价的 datapath 或最小的原始数值宽度。它将 NVFP4 类保留为有损的 4-bit width 前沿，而非质量通过点，同时记录了其相比 MXFP4/MXINT4 更高的 scale 路径面积。对于 P3109，可用区域向上移动：4-bit 形态作为控制点，6-bit 的 b6p5sf 是具有存储路径杠杆的中等成本质量通过点，而 8-bit 的 b8p5sf/b8p6sf/b8p7sf 点只有在所采用的工作负载套件中将其点估计视为近基线平局之后，才成为存储/复用的决策。

同一阶梯还接受了 38 个面向 AMD、Huawei 和 NVIDIA 的公开别名或代理。其中九个达到全流程均值预算。AMD/OCP E4M3 是最强的厂商重放；其 g16 点使 PPL 变化 0<sub>.</sub>055，任务准确率变化 −0<sub>.</sub>022 pp。E2M3 再次表现出指标分离：g128 给出最低的 PPL 变化量，而 g32 给出最佳任务结果。FNUZ、HiFloat 类以及无旋转的 NVE0M3 代理在该固定的 RTN/PTQ 配方下不会改变候选短名单。补充表 S2 给出了代表性行；工件（artifact）中包含完整的语义映射。

1) 实验覆盖与 OCP/NV/INT 前沿：工件清单保留了完整矩阵：288 行 OCP/NV/INT PPL 数据、296 行 E2E 数据、24,192 行 P3109 QSNR 数据、320 行实用 P3109 PPL 数据、96 行 P3109 任务数据，以及综合/复用表。补充表 S1 记录了各阶段的调用与决策规则。

mxint8\_g16 是最稳定的 OCP 类 8-bit 参考点，其平均 PPL 变化量为 −0<sub>.</sub>004824，平均 PIQA/ARC-Easy 变化量为 0<sub>.</sub>031886 pp。其各模型的差值范围为 −0<sub>.</sub>153467 至 0<sub>.</sub>159625，且其任务均值方向分裂，使其落入平局区间。4-bit 的结果更为清晰。nvfp4\_g8 平均损失 0<sub>.</sub>505120 pp，但仍比 mxint4\_g8 好 0<sub>.</sub>856 pp，并且在全部八个模型均值上均为负值。所记录的 seed-0 随机值消融（ablation）中没有点被提升至 Pareto 短名单。

我们还合成了对应的 OCP 类算术单元作为候选级 RTL 原型。每个单元是一个 16-lane 的块缩放点积，具有共享的 scale 解码和定点累加 datapath。一个有界的单 lane SymbiYosys 证明在符号编码上检查了解码、scale 移位和符号处理；Chisel 测试针对独立的定点参考实现覆盖了多 lane 累加。最终短名单将这些 PPA 行纳入质量-成本决策：整数 4-bit datapath 面积最小，但其工作负载损失大于 NVFP4 类 FP4；MXINT8 仍作为近基线的 8-bit 参考点，但其算术单元面积更高。

2) 算子感知的低/高模式分配：算子策略试点发现了结构化的精度敏感性。从观测到的最佳低精度模式 nvfp4\_g8 和近基线的高精度模式 mxint8\_g16 出发，它在基线、全低、全高、单类降级和单类挽救策略下评估 Qwen3-8B、Llama-3-8B 和 Mistral-7B。57 行完整的 WikiText-2 数据覆盖了 attention 投影、FFN 投影和 lm\_head。

全低配置的退化程度与模型相关：nvfp4\_g8 使 Qwen3-8B 的 PPL 增加 1<sub>.</sub>174，Llama-3-8B 增加 0<sub>.</sub>649，Mistral-7B 增加 0<sub>.</sub>346；而全高的 mxint8\_g16 则基本保持在基线水平，变化量分别为 −0<sub>.</sub>024、−0<sub>.</sub>014 和 −0<sub>.</sub>005。最一致的挽救目标是 down\_proj；它是 Llama-3-8B 和 Mistral-7B 的首选挽救对象，平均可恢复全低配置 PPL 退化的 38<sub>.</sub>3%。lm\_head 尽管只包含一个线性层，也表现出一致的敏感性。这就是软件/硬件协同设计的关键点：架构无需实现逐算子的 datapath，但精度菜单应以一种允许编译器或运行时选择性地将高精度分配给敏感的复合算子区域的方式暴露出来。

区域级的提升结果十分紧凑。没有任何 4-bit P3109 提升点能达到接近基线的 PPL 区间。十个 6-bit PPL 点中有八个做到了，其中以 b6p5sf 为首；全部二十个 8-bit PPL 点均做到。PIQA/ARC-Easy 关键点呈现出相同的模式，因此 P3109 的推荐并非由某一行有利数据所驱动。

更强的三项任务检查并未推翻区域级的设计规则。nvfp4\_g8 仍是支撑最充分的 4-bit 入围者，但它在 ARC-Challenge、HellaSwag 和 WinoGrande 上平均损失 0.403 pp。接近基线的集群非常紧凑：mxint8\_g16、p3109\_b8p6sf\_g64 和 p3109\_b8p7sf\_g16 在聚合指标上均与基线相差不超过 0.013 pp。6-bit 的 p3109\_b6p5sf\_g8 点在更难的任务上并未崩溃。其正向均值仍只是一个点估计，因为逐模型的范围仍然很宽。

这些额外的完整基准测试行最适合作为机制层面的检查。它们支持 6-bit P3109 中间区域，并在质量接近基线时将 8-bit P3109/MXINT8 留作存储或复用层面的决策。它们并不以统计置信度对接近基线的集群进行排名。

## B. RQ2：配方边界检查是否与 PTQ 短名单相矛盾？

训练检查提出的是一个狭窄的问题：一旦量化参与到优化之中，它是否会立即反转由推理导出的区域？一个字节级因果语言模型（causal LM）和一个 BERT 风格的掩码语言模型（masked LM）各自处理 4.19M 个训练 token、运行 512 个优化器步数，使用 STE 伪量化的 Linear 权重，并在完整的 WikiText-2 验证流上打分。第二个配方在全部 67,349 个 SST-2 训练样本上对 5.97M 参数的 TensorGauge 风格 BERT 模型训练三个 epoch，并评估全部 872 个验证样本。

长期运行的 LLM 训练可能会重排这些候选者。网格几何结构、旋转（rotations）、随机舍入（stochastic rounding）、缩放层级与裁剪（clipping）都各有影响 [28]–[30]。这些方法是在数值支持存在之后定义训练配方；本文的实验为流片前（pre-silicon）短名单提供一个小规模的训练侧检查。

补充材料图 S1 使结果直观可见。NVFP4 类似的 4-bit 在因果语言模型运行中仍比 MXFP4 更安全；MXINT8 和实用的 P3109 点保持在基线附近。掩码语言模型的差异收窄至 −0.004–+0.013 PPL。在 19 个实用的 SST-2 候选者中，准确率围绕 1.339 点的基线标准误变化 −0.803–+1.491 个百分点。这解决的是一致性问题，而非选出胜者。

对第二个操作数路径进行量化也不会使实用短名单崩溃。在 Mistral-7B 和 Qwen3-8B 上，在每个 Linear 之前进行 MX-INT8 g64 的仅激活量化会使平均 PPL 变化 +0.012155。在相同的激活路径下，b6p5sf\_g8 权重使总 PPL 变化 −0.024343，b8p6sf\_g64 变化 −0.000380，而 NVFP4 变化 +0.713790。这一 W/A8 重放是一个双模型边界检查，而非激活校准的部署配方；其作用是测试当激活也以低精度表示时，仅权重（weight-only）的 4/6/8-bit 区域是否会立即反转。它们并不会。

一个共同的裁剪压力测试改变的是预算通过情况，而不仅是排名。在 max-abs 缩放下，NVFP4 类似方案、b6p5sf 和 b8p6sf 在 Mistral-7B 和 Qwen3-8B 上的平均 PPL 差异分别为 0.710、−0.048 和 −0.012。对每个 Linear 施加固定的 0.9×-max 裁剪后，它们变为 1.192、0.271 和 0.211。6-bit 和 8-bit 候选者均从 0.1-PPL 平均预算之内移动到之外，且它们的顺序发生了互换。这一共享裁剪操作是一个可复现的压力测试，而非校准的生产配方。它表明 max-abs 短名单必须在预期配方下重新验证；补充材料表 S8 给出了模型级的数值与协议细节。

## C. RQ3：为什么 group size 和 QSNR 不是简单的排序器？

Group size 之所以无法作为单调排序器，是因为独立缩放的较小分组会改变量化器。图 3 中的受控重放从全部八个 LLM 中抽取 Linear 权重行。当每个 $\mathtt { g 8 }$ 子分组继承其 g16 父分组的 scale 和最近邻投影时，全部 1,344 个采样张量完全匹配。而独立的 $\mathtt { g 8 }$ 量化则会改变 23<sub>.</sub>2– 45<sub>.</sub>9% 的 scale 编码，并且对于 FP4 类格式，还会改变截断（clipping）模式。随后的完整 WikiText-2 PPL 在两个方向上均有变化。g16 在 MXFP4、MXINT8 和 b8p7sf 上取得的微弱总体优势仍然处于或接近平局容忍带之内；它们并不能证明更大分组具有内在优势。

P3109 任务关键点在更大分组间隔下也得出相同结论。最佳的 6 位和 8 位分组在总体指标上略有差异，但逐模型、逐任务的符号在所采用的平局容忍带内出现分裂。因此，对更大分组的微弱总体偏好并不构成一条单调的分组大小规则。

QSNR 的局限性在实际位宽内部即可观察到。在 40 个晋升的 P3109 候选方案中，QSNR 与平均 PPL 增量的 Spearman 相关为 $\rho ~ = ~ - 0 . 9 6 8$，Pearson 相关为 $r ~ = ~ - 0 . 8 1 9$，但在 6 位区域内部进行精细排序时，该关系会变弱 $( \rho = - 0 . 5 2 7 )$。QSNR 能清晰地将高损失的 4 位形态与 6/8 位区域区分开；而接近平局的候选方案之间的最终裁决仍需依赖完整 PPL 与下游任务。

因此，保留验证将三种主张区分开来。QSNR 在 budget 为 28 时能达到实际 40 点全集中的全部 28 个平均预算点，但在每一个更小的 budget 下它并非更优的 frontier 排序。当每个具名模型家族被逐一从 QSNR 排序中剔除时，accepted recall 的范围为 90<sub>.</sub>9% 至 100%；对于 Qwen2.5，width priority 仍多保留一个 accepted 点。候选全集和 budget 均继承自全量数据研究，因此这属于敏感性证据，而非前瞻性验证。在更广泛的 56 点 width 审计中，QSNR 也未能完整召回单模型 frontier。将不规则位宽对照方案排除在所提议的菜单之外，是基于生态适配性的考量，而非数值无效性。

对于 OCP/NV/INT $( r = - 0 . 9 8 1 )$ 和 P3109 关键点 $( r = - 0 . 9 9 7 )$，PPL 与 PIQA/ARC-Easy 保持一致。强任务决赛选手能保留粗粒度的区域标签，但无法解决接近基线处的排序问题。因此，QSNR 是一种有用的受限空间优先级信号。它既不是准入策略，也不是最终门槛。

在接近基线时，排名变得不稳定。对于五个决赛选手，PPL 与 ARC-Challenge/HellaSwag/WinoGrande 的 Pearson 相关为 $r = - 0 . 9 4 5$，但 Spearman 相关仅为 $\rho ~ = ~ - 0 . 3 0 0$；双任务代理指标与这些更强任务的相关性同样为 $r = 0 . 9 0 5$ 和 $\rho =$ 0<sub>.</sub>100。这些指标能够区分高损失的 4 位区域，但无法对 6/8 位簇进行排序。Seed-0 随机值 PTQ 也被降级：全部 18 个点相对最近邻舍入平均使平均 PPL 恶化 1<sub>.</sub>356，平均 PIQA/ARC-Easy 增量变化为 −1<sub>.</sub>233 pp。

工件中包含一个平局容忍的 Pareto 重放。将低于 0.01 PPL 和 0.15 pp 的差异折叠后，观测到的 storage/PPL 和 area/task frontier 分别从 12 个点缩减至 9 个、从 6 个点缩减至 3 个。其结论保持不变：4 位 P3109 是压力区域，6 位 P3109 是低面积中间档，而 8 位的近似平局由存储与复用性决定。

## F. RQ5：可以得出哪些设计规则？

实用估计揭示了三个区域。在 58 个存储/PPL 候选中，有 12 个是原始非支配点；30 点的面积/任务视图有六个原始前沿点。一旦将近零的点估计视为未解决的平局，8-bit 便成为质量参考而非成本赢家。NVFP4 类格式在固定配方下仍是最强的已测试 4-bit 点，而 6-bit P3109 尽管任务区间更宽，仍保留了独特的成本角色。这是在所声明的面向 GPU 的范畴内的一个候选名单，并非对所有 P3109 位宽或量化配方的全局最优。

TensorGauge 表明，局部误差特征可以在端到端训练稳定之前先行稳定。因此 TensorExplorer 利用它们进行剪枝，而工作负载则设定有用的精度裕度。

## VII. 架构启示与适用范围

在所测试的 RTN/PTQ 协议下，证据支持一个紧凑的候选集合：具备范围感知的 4-bit、具有成本优势的 P3109 b6p5sf，以及保守的 8-bit。6-bit 的任务区间仍悬而未决。在 $\boldsymbol{g} = 16$ 时，6/8-bit 拆分流每 128 个权重传输 104/136 B，而其 K16 单元占据 4188/5277 $\mu \mathrm { m } ^ { 2 }$。6-bit 在字节通道暂存（byte-lane staging）之前仍保持存储与算术上的中间地带。

混合模式无需实例化完整的笛卡尔积。DeepSeek-V4 促使采用 FP4 权重/FP8 计算，而当前的 MMA 接口已暴露独立的 A/B 类型 [11], [12]。我们的 MXFP8×MXFP4 K16 块相对于对称的 MXFP8 节省了 9.66% 的面积。E2M3 的反演（reversal）仍要求对每一对保留的组合进行实测。

分组大小（group size）与算子分配仍属于软件策略，因为缩放与敏感度依赖于具体模型。硬件暴露的是稳定的数值、缩放、舍入与累加语义。TensorExplorer 在 ISA 编码、操作数传送、调度与物理收敛之前返回这一契约，以及打包与累加器指导、可复用模式的成本，以及选定的操作数组合。新的厂商格式、自适应 IF4 以及 P3109 候选格式均通过同一经过审计的接口接入。

KDA 案例将这一契约扩展到了外部数据类型之外。“FP32 输入”并未指明内部的乘法精度、累加语义，或依赖执行路径的精度选择。编译器/内核接口应当显式地提供快速 TF32 路径与精度敏感的 TF32x3 或 IEEE 路径，而不是依赖隐式默认值。高精度模式不仅应分配给敏感的神经网络算子，还应分配给数值上深层的状态传播区域。先前算子感知的结果由此升级为执行路径感知的精度：即使在同一算子内部，局部递归与上下文并行的仿射前缀也可能需要不同的内部精度。

## VIII. 相关工作

IEEE 754、OCP microscaling、P3109 以及各厂商格式定义了数值契约 [1]–[10], [31]。NVIDIA 的块缩放（block-scaled）接口允许独立的 FP8/FP6/FP4 操作数类型，而 DeepSeek-V4 促使采用 FP4 权重/FP8 计算的非对称方式 [11], [12]。自适应块缩放 IF4 则针对每个 16 值分组选择 INT4 或 FP4，并评估与之匹配的 MAC [32]。它提出了一种新的自适应编码；TensorExplorer 则提供了互补的 ISA 前测试，用于检验此类契约能否经受工作负载与实现成本的考验。可重构算术随后实现所选定的候选集合 [19]–[22], [33]。

HAQ、HAWQ、AdaRound、GPTQ、SmoothQuant 与 AWQ 优化模型如何使用可用精度 [13]–[18]。训练研究进一步揭示了网格几何、旋转、裁剪与随机估计带来的影响 [28]–[30]。TensorExplorer 则刻意保持量化方案简单，转而追问何种契约值得在硬件层面跨模型地暴露。

Accel-Sim 对 GPU 执行进行建模；MMA-Sim 与特性刻画研究还原了矩阵单元的算术行为 [34]–[37]。TensorGauge 将内部语义与工作负载关联起来 [38], [39]。本工作沿这一路径进一步扩展，通过格式枚举、完整工作负载、打包与综合，在量化与 Tensor Core 集成之间产出候选短名单。

Kimi Linear 提出了 KDA，FLA 提供了其开源的上下文并行仿射合并 [23], [24]。FLA PR #1180 是一项工程上的精度选择，而非由 TensorExplorer 生成的证据 [26]。Triton 文档指出 TF32 是 NVIDIA 上 FP32 tl.dot 输入的默认值，并暴露 TF32x3/IEEE 备选方案 [25]；Ootomo 与 Yokota 提出了高精度多 TF32 GEMM 技术 [27]。Tensor-Explorer 并未发明 TF32x3。它将局部算术语义、执行路径组合与工作负载可见的筛选，连接到 ISA 之前的架构决策。

## IX. 结论

TensorExplorer 将数值格式的选择转变为一个可审计的流片前决策。完整工作负载区分出一个有损但为最强测试配置的 4-bit 点位、一个任务区间尚无定论且具成本优势的 6-bit 中间档，以及保守的 8-bit 参照。预算扫描确立了 QSNR 作为一种条件化剪枝辅助手段，其优势随目标与阈值而变化。打包、有限比例重放、非对称操作数组合以及 22 nm 单元 PPA 暴露了相应的实现后果。KDA 压力测试案例补充了一个横切边界：在执行图反复组合表示与局部算术之处，同样必须对其进行检验。最终产出是一份执行模式候选短名单，其质量、方案敏感性、算术成本与路径绑定均可在 ISA 与 Tensor Core 集成之前予以审视。
